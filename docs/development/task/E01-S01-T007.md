## 2. 任务目标与边界

本任务审计并固化 Sweet Platform 现有功能权限链路：

```text
sys_menu
  -> sys_menu_button
  -> sys_role_menu / sys_role_menu_button
  -> Casbin
  -> /admin/menu/my
  -> usePageButtons
```

职责边界：

1. `sys_menu` 控制用户可进入的页面和可生成的动态菜单。
2. `sys_menu_button` 定义页面操作及其可选 API path/method。
3. `sys_role_menu` 和 `sys_role_menu_button` 保存角色授权关系。
4. Casbin 使用角色或用户主体、路由模板和 HTTP method 控制接口调用。
5. `usePageButtons` 只负责展示当前菜单已授权且可用的页面按钮。
6. 前端隐藏按钮不是安全边界，后端 Casbin 或控制器业务权限检查仍是最终保护。

本任务不处理数据权限、组织权限、ABAC、权限模型重构，也未新增菜单、按钮、Casbin seed 或业务 action。

### 4.4 前端按钮解析

原 `usePageButtons` 在 composable 内递归查找菜单，并只按 `is_button` 过滤。虽然后端已经过滤停用和禁用按钮，前端缺少防御性约束，隐藏按钮仍可能进入页面按钮集合。

本任务将解析收敛到可独立测试的公共函数：

- `findMenuByName`
- `isAvailablePageButton`
- `resolvePageButtons`

`usePageButtons` 现在只返回：

1. 当前 route name 对应菜单下的按钮；
2. `is_button=true`；
3. `state` 未停用；
4. `is_hidden` 未隐藏；
5. `is_disabled` 未禁用；
6. 按 `sequence` 排序。

`isApiPermission` 继续只依据 `is_button=false` 分类，隐藏页面按钮不会被误分类为 API-only 权限。

## 5. 标准功能权限链路

### 5.1 定义

1. 正式页面必须定义 `sys_menu`。
2. 正式页面操作优先复用工程手册中的标准 action。
3. 受保护操作必须定义 `sys_menu_button`。
4. 页面按钮使用 `is_button=true`；仅用于接口授权的配置使用 `is_button=false`。
5. 需要 Casbin 保护的按钮必须配置规范化 route template 和大写 HTTP method。

### 5.2 授权

1. 角色菜单写入 `sys_role_menu`。
2. 角色按钮写入 `sys_role_menu_button`。
3. 按钮必须属于已授权菜单。
4. 停用或禁用按钮不得成为新授权。
5. 有 API path/method 的按钮同步为 Casbin policy。
6. 删除菜单或按钮时继续使用现有清理链路删除失效关系和孤立策略。

### 5.3 执行

1. Auth middleware 先确认登录身份。
2. Casbin middleware 以 route template + method 校验 API 功能权限。
3. 复用路径无法唯一表达业务资源时，由控制器继续校验 menu/action。
4. Service 负责业务前置条件。
5. 数据权限属于独立链路，本任务不改变。

### 5.4 前端

1. `/admin/menu/my` 是当前用户菜单和按钮授权的权威响应。
2. 页面操作统一通过 `usePageButtons(routeName)` 读取。
3. 页面不得通过角色名硬编码显示按钮。
4. 前端隐藏或禁用按钮只改善体验，不能替代后端权限校验。

## 9. 遗留问题

以下为审计发现的历史问题，本任务按边界只记录：

1. `AssignPermissions` 先提交角色关系数据库事务，再更新 Casbin；Casbin 更新失败时会恢复旧 policy，但角色关系与 policy 仍存在短暂或失败后的不一致风险。后续应作为独立一致性任务评审补偿方案。
2. 开发配置当前关闭 Casbin policy 全覆盖，未登记 policy 的接口可按兼容模式通过；生产和 Docker 配置已启用严格覆盖。新增接口仍必须配套按钮与 policy 测试。
3. `SysRoleMenuButtonRepositoryImpl.GetRoleMenuButtons` 使用 association preload 条件，查询语义需要独立 Repository 回归测试确认；该文件是任务开始前已有未提交改动，本任务未触碰。
4. 少数历史页面直接使用 `isPageButton`，没有统一走 `usePageButtons`；应按页面逐步迁移，不能在本任务批量改造。
5. 当前前端没有统一测试脚本，本任务使用 Node 22 内置 test runner 验证纯解析函数，未引入新依赖或测试框架。
