## 5. 查询协议与时间语义

统一查询接口使用 `time_scope`：

| `time_scope` | 语义 | 默认排序 |
| --- | --- | --- |
| `current` | `status=enabled`、未源删除，且 `valid_from <= as_of_date <= valid_to` | `valid_from` 倒序、ID 倒序 |
| `history` | 已停用、已源删除或 `valid_to < as_of_date` | `valid_to` 倒序、ID 倒序 |
| `future` | `status=enabled`、未源删除，且 `valid_from > as_of_date` | `valid_from` 正序、ID 正序 |
| `timeline` | 该员工保留的全部任职镜像 | `valid_from` 倒序、ID 倒序 |

规则：

1. `time_scope` 为空时默认为 `current`。
2. `as_of_date` 为空时使用平台当前时间，显式值格式为 `YYYY-MM-DD`。
3. `valid_from` 和 `valid_to` 当日均为包含边界。
4. `timeline` 中每条记录仍标记自身的 `current/history/future` 分类。
5. 历史查询只返回本地已保存的镜像记录，不推断或补造权威源未提供的历史。
6. 一个员工的多条任职全部保留，不去重、不选第一条。

## 6. API 与权限

| Method | Path | Action | 用途 |
| --- | --- | --- | --- |
| POST | `/admin/org/assignment/query` | `query` | 按员工和 `time_scope` 分页查询任职 |
| GET | `/admin/org/assignment/:id` | `detail` | 按内部 `assignment_id` 查询详情 |
| GET | `/admin/org/employee/:id/assignments/summary` | `query` | 查询全部当前任职的法人、组织和岗位去重集合 |

上述权限挂在既有“人员与任职”菜单下，通过 `sys_menu_button`、`sys_role_menu_button` 和 Casbin 幂等补齐，默认授权 `super_admin`。没有新增权限模型、角色名判断或数据权限。

## 7. Repository 与 Service 边界

Repository：

1. 使用参数化条件执行时间范围过滤、关联 ID 过滤、AdvancedQuery 和分页。
2. 只选择白名单字段，源内部字段仅在 Service 分类所需时内部读取 `source_deleted`。
3. 为时间轴提供确定性数据库排序。
4. 不判断权限、不选主任职、不修改任职。

Service：

1. 校验员工存在和内部 ID。
2. 统一解析 `time_scope/as_of_date`。
3. 将 Model 映射为 Assignment Response DTO。
4. 批量查询法人、组织和岗位摘要，避免逐行 N+1。
5. 汇总全部当前任职的关联集合，不提供主项或默认项。
6. 只读查询不开启无意义事务。

## 8. DTO 与信息边界

Assignment Response DTO 允许返回：

- 平台内部 `assignment_id`
- `employee_id`、`legal_entity_id`、`org_unit_id`、`position_id`
- 任职类型、源镜像主/负责人标记、状态和有效期
- 时间分类
- 法人、组织、岗位的安全编码和名称摘要

禁止返回：

- `source_system_code`
- `source_id`
- `source_version`
- `source_deleted`
- `sync_status`
- 同步内部错误字段
- `sys_user` 对象、密码、令牌、角色或权限

历史或停用的关联对象通过内部 ID 批量回显，用于只读展示；它们不会因此重新成为可选的新值。
