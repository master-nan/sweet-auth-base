# E02-S06-T001 Organization Read-only Center

## 1. 任务目标

建设 Organization Foundation 的首批只读展示页面：

1. 法人架构。
2. 管理架构。

页面只消费外部主数据同步形成的本地镜像，不提供新增、编辑、删除、组织调整、调岗或离职入口。本 Task 不实现人员、岗位或同步页面。

## 2. 开始前工作区状态

任务开始前工作区已有 Report、Frontend、design 和相关文档的未提交改动。本 Task 未覆盖、回滚或提交这些历史改动。

其中 `frontend/src/router/routes.ts` 已包含用户未提交的 Report V2 路由改动。本 Task 仅增加 Organization 固定路由，提交时必须按补丁精确暂存该文件中的 Organization 路由片段。

## 3. 页面结构

### 3.1 法人架构

路由与页面：

- 路由：`/admin/organization/legal-entity`
- route name：`organization_legal_entity`
- 页面：`pages/organization/legal-entity/Index.vue`

布局复用：

- `BaseContent + q-pa-sm`
- `MasterDetailPage`
- `TreeTable`，内部使用平台 `q-table`
- 右侧详情字段网格参考 `RecordDetail`

左侧直接展示后端法人树，节点业务标识为 `legal_entity_id`。支持按法人编码、名称和简称过滤，保留命中节点的祖先上下文。

右侧通过独立详情 API 展示法人编码、名称、简称、主体类型、状态、有效期、统一社会信用代码、核算编码、镜像更新时间和平台备注。当前详情 DTO 不提供源系统标识，因此页面不推测或拼接来源信息。

### 3.2 管理架构

路由与页面：

- 路由：`/admin/organization/structure`
- route name：`organization_structure`
- 页面：`pages/organization/structure/Index.vue`

左侧以稳定 `structure_code` 作为架构切换值，再使用对应内部 `structure_id` 请求组织树。节点定位使用 `structure_node_id`，详情请求与业务语义使用 `org_unit_id`。

同一 `org_unit_id` 在同一或不同架构中出现多个节点时，前端不会按组织 ID 去重，仍保留每个 `structure_node_id` 的树位置。

右侧展示组织编码、名称、类型、状态、有效期、所属管理架构、架构层级、节点状态、主要法人、镜像更新时间和平台备注。

## 4. API 调用

| 页面 | Method | API | 用途 |
| --- | --- | --- | --- |
| 法人架构 | POST | `/admin/org/legal-entity/tree` | 查询法人树 |
| 法人架构 | GET | `/admin/org/legal-entity/:id` | 查询法人详情 |
| 管理架构 | POST | `/admin/org/structure/options` | 查询管理架构选项 |
| 管理架构 | POST | `/admin/org/unit/tree` | 查询指定架构组织树 |
| 管理架构 | GET | `/admin/org/unit/:id` | 查询组织单元详情 |

所有调用统一收敛在现有 `frontend/src/api/services/org.ts`，页面不直接使用 Axios，不从平面列表自行拼装组织树。

## 5. 权限边界

1. 页面复用 `usePageButtons`。
2. tree、options 使用现有 `query` Casbin 权限。
3. 详情按钮与详情请求使用现有 `detail` 权限。
4. 现有 `refresh` 页面按钮仅重新执行只读查询。
5. `view_sync` 不在本 Task 页面展示。
6. 不增加菜单、按钮、Casbin Policy 或数据权限。
7. 页面不存在 create、update、delete、调岗、离职或组织调整操作。

## 6. UI 基线说明

树页面复用 `MasterDetailPage + TreeTable`，没有新增第二套列表、查询、分页或详情布局。

`AdvancedQuery` 和 `TablePagination` 适用于分页列表；本 Task 的核心数据源是已评审的非分页树 API，因此不在树视图中制造无效分页或把 AdvancedQuery 表达式错误传给树接口。`RecordDetail` 作为右侧字段展示和错误/空状态的视觉基线，不直接嵌套其路由型页面组件。

自动化交互验收覆盖：

1. 法人树展示和首条详情联动。
