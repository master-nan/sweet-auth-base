## 4. 模型设计摘要

### 4.1 正式模型

| 模型 | 表名 | 领域职责 |
| --- | --- | --- |
| `OrgLegalEntity` | `org_legal_entity` | 法人或核算主体只读镜像，法人层级使用 `parent_id` |
| `OrgUnit` | `org_unit` | 管理组织主体只读镜像 |
| `OrgStructure` | `org_structure` | 管理架构定义 |
| `OrgStructureNode` | `org_structure_node` | 管理架构树运行节点，使用 `path + level` |
| `OrgPosition` | `org_position` | 组织内岗位只读镜像，不等同于角色 |
| `OrgEmployee` | `org_employee` | 企业人员只读镜像，`user_id` 仅为可空平台账号绑定 |
| `OrgAssignment` | `org_assignment` | 员工任职镜像，支持一人多岗和有效期 |
| `OrgSyncBatch` | `org_sync_batch` | 组织业务同步批次结果，不保存 HTTP 技术日志 |
| `OrgSyncRecord` | `org_sync_record` | 单对象业务同步结果，不替代 Integration Execution/Payload |

所有模型复用 `model.Basic`。因此内部主键及关联字段沿用项目现有 `int/bigint` 约定；未新增第二套主键或审计字段。

### 4.2 对象边界

1. 法人使用 `legal_entity_id`。
2. 管理组织使用 `org_unit_id`。
3. 企业人员使用 `employee_id`。
4. 岗位使用 `position_id`。
5. 系统账号使用 `user_id`。
6. 模型中未引入模糊的 `organization_id`。
7. 业务关联未保存 `org_structure_node_id`。
8. 未引入 closure table、nested set、图数据库、本地组织维护模型或已裁剪的扩展表。

### 4.3 Source 与 Platform 字段

模型通过字段分组注释明确源字段和平台扩展字段：

- Source/运行字段包括稳定源键、名称编码、上下级、状态、有效期、源版本、同步状态和最近错误。
- Platform 字段包括 `org_employee.user_id`、`local_note`、`local_tags`、`display_order` 和 `local_handling_status`。

本任务只定义模型边界。后续 Service 必须使用 source update DTO/白名单和 platform extension DTO/白名单，禁止整行 `Save` 覆盖平台字段。

### 4.4 主要数据库约束

1. 各源镜像对象使用 `source_system_code + source_id` 稳定唯一键。
2. 标准 code、employee_no、batch_no 按评审结论设置唯一约束。
3. 可空 source_code 和统一社会信用代码使用 PostgreSQL partial unique index。
4. `org_employee.user_id IS NOT NULL` 时唯一，允许多个未绑定员工。
5. 同一 structure 下同一 org_unit 仅允许一个当前有效节点。
6. 同一员工仅允许一个当前、启用、未删除且无结束时间的主任职。
7. 同一组织岗位 code 在当前有效范围内唯一。
8. 复杂任职时间区间重叠、组织循环和默认架构唯一仍由后续 Service 校验，不在 Model 中伪造完整业务规则。

### 7.2 PostgreSQL 专属验证

新增显式环境测试 `TestOrganizationPostgreSQLPartialUniqueConstraints`。默认无 DSN 时跳过；提供 `SWEET_TEST_POSTGRES_DSN` 时使用独立临时 schema，测试结束自动清理。

本任务在本地 PostgreSQL 16 容器实际验证：

1. source_code、统一社会信用代码等 partial unique index 已创建。
2. 非空 `org_employee.user_id` 重复绑定被拒绝。
3. 同一 structure/org_unit 当前有效节点重复被拒绝。
4. 同一员工当前主任职重复被拒绝。

复杂有效期重叠不由当前 partial index 完整覆盖，后续需由 Service 校验；如未来采用 exclusion constraint，必须另行做真实 PostgreSQL 评审和测试。
