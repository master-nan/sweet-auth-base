## 4. Metadata 与渲染规则

`AdvancedQuery` 直接复用 `resolveOrganizationSelectorConfig`，支持：

| `selector_type` | 查询值语义 |
| --- | --- |
| `legal_entity` | `legal_entity_id` |
| `org_unit` | `org_unit_id` |
| `employee` | `employee_id` |
| `position` | `position_id` |

当 resolver 返回有效配置时，规则行渲染现有 `OrganizationSelect`，并传递：

- `modelValue`
- `selectorType`
- `includeHistory`
- `disabled`
- 查询校验规则

选择器元数据优先于旧字典和 linkage 控件；该字段不会再触发旧字典或关联选项预加载。
无 selector 配置时，文本、数字、日期、字典、布尔和关联字段继续使用原有查询分支。
根规则和嵌套规则使用同一处理链路。

## 5. 运算符与值边界

Organization Selector 字段只开放：

- `=`：单选，查询值为一个正整数内部 ID。
- `in`：多选，查询值为正整数内部 ID 数组。

AdvancedQuery 中的单选或多选形态由当前查询运算符决定，不使用表单 metadata 的
`multiple` 改变运算符语义。

提交边界：

1. 仅接受正安全整数 ID。
2. 合法数字字符串转换为 number。
3. 多选值自动去重。
4. label、name、对象及其他非 ID 值被丢弃。
5. 已保存的查询条件在显示或提交前执行相同归一化。
6. `employee` 查询值始终为 `employee_id`，不会使用 `user_id`。

本 Task 不支持组织树、下级组织展开、descendant 运算符或数据权限范围解析。
