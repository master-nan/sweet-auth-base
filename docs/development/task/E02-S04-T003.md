## 4. Selector Metadata 协议

支持四种标准 `selector_type`：

| selector_type | 持久化值 |
| --- | --- |
| `legal_entity` | `legal_entity_id` |
| `org_unit` | `org_unit_id` |
| `employee` | `employee_id` |
| `position` | `position_id` |

直接字段元数据示例：

```json
{
  "input_type": "selector",
  "selector_type": "employee",
  "multiple": false,
  "include_history": false,
  "disabled": false
}
```

为兼容已评审的 `linkage_config` 方案，resolver 同时识别其中的：

- `legal_entity_select`
- `org_unit_select`
- `employee_select`
- `position_select`

这些别名只在运行时归一化为四种标准 selector，不改变持久化 ID 语义。

## 5. Resolver 设计

`resolveOrganizationSelectorConfig(fieldMetadata)` 返回：

```json
{
  "selectorType": "employee",
  "multiple": false,
  "includeHistory": false,
  "disabled": false
}
```

解析规则：

1. 字段顶层 `selector_type` 优先。
2. 顶层未配置时，读取 `linkage_config.selector_type` 或 `linkage_config.selector.selector_type`。
3. `multiple`、`include_history`、`disabled` 按字段顶层、嵌套 selector、linkage 根配置的顺序解析。
4. 布尔配置兼容 boolean、`0/1` 和 `"true"/"false"`。
5. 没有 selector 配置时返回 `null`。
6. 显式未知 `selector_type` 返回 `null`，不静默降级为另一种 selector。
