# E02-S06-T001-R2 Organization Center UI Information Architecture Refinement

## 1. Task 目标

在不修改组织模型、API 和组织树算法的前提下，优化组织主数据中心的信息层级与可见表达：

- 将“组织架构”调整为组织主数据的首要入口。
- 保留“法人主体”独立入口，并将页面定位为法人档案浏览。
- 仅在存在多套 Structure 时显示“组织视图”选择器。
- Structure 的可见名称完全来自后端数据，不暴露编码或默认标记。
- 保持树节点点击查看详情、展开操作仅控制树展开。

## 2. 开始前工作区状态

任务开始前工作区已有 Report、Frontend、design 等历史未提交改动。本 Task 不覆盖、不回滚、不暂存这些改动。

## 3. 菜单结构

组织中心的目标信息架构为：

1. 组织架构
2. 法人主体
3. 人员
4. 岗位
5. 任职
6. 同步记录

本 Task 仅落地已实现页面的主次顺序，将“组织架构”置于“法人主体”之前。人员、任职和同步相关入口的拆分与改名不在本 Task 范围，现有入口保持不变。

## 4. 页面规则

### 4.1 组织架构

- 页面名称保持“组织架构”。
- 单一 Structure 时自动加载并隐藏选择器。
- 多 Structure 时显示“组织视图”选择器。
- 选项仅展示后端返回的 Structure 名称。
- 不展示 Structure 编码、“默认”等技术表达。
- 不展示 `structure_node_id`、`parent_node_id`、`path`、`level`、`source_id`。

### 4.2 法人主体

- 菜单名称保持“法人主体”。
- 页面主区域定位为“法人档案”。
- 法人树用于档案浏览，不作为管理组织树入口。
- 点击法人节点加载详情，不提供重复详情按钮。

## 5. 修改范围

- 组织菜单 Seed 的顺序与幂等回归断言。
- 前端静态路由中的组织入口顺序。
- 法人主体与组织架构页面的展示文案。
- 组织只读中心页面测试。

未修改后端模型、组织 API、组织树算法、权限模型和 CRUD 能力。
