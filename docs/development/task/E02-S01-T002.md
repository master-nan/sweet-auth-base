## 2. 任务目标

本任务将 E02-S01-T001 建立的九类组织主数据镜像模型接入现有平台基础能力：

1. 组织字典与菜单动作字典。
2. `sys_table` 与 `sys_table_field` 元数据。
3. 组织主数据目录及六个功能菜单。
4. 只读镜像所需按钮权限。
5. `super_admin` 角色菜单、按钮和 Casbin policy。
6. 两轮 Seed 幂等回归测试。

本任务不开发 Repository、Service、Controller、API、页面、Selector、真实源系统同步或数据权限。

## 6. 元数据设计

### 6.1 `sys_table`

九张组织表均通过稳定 `table_code` 登记为平台系统表：

1. `org_legal_entity`
2. `org_unit`
3. `org_structure`
4. `org_structure_node`
5. `org_position`
6. `org_employee`
7. `org_assignment`
8. `org_sync_batch`
9. `org_sync_record`

组织 Seed 复用现有 `platformSeedSteps()`，在 `sys_table_and_field_metadata` 步骤完成通用元数据扫描后执行，不新增第二套 Seed 注册机制，也不改变已冻结的 Seed 步骤顺序。

### 6.2 `sys_table_field`

每张物理表的字段均登记元数据，并统一设置：

- `is_insert_show = false`
- `is_update_show = false`

因此 `sys_table` 登记不代表开放普通 CRUD。

列表和查询只开放业务需要字段：

- 法人、组织、岗位、人员的编码、名称、类型、有效状态和必要关联 ID。
- 人员的 `user_id` 显示名固定为“绑定账号”，仍由后续专用绑定动作维护。
- 任职的人员、法人、管理组织、岗位、类型、主任职、负责人和有效期。
- 同步批次与同步记录的运行状态、计数、错误码、依赖和重试信息。

以下字段仅登记但不进入普通列表、快捷查询或高级查询：

- `source_id`
- `source_version`
- 镜像对象内部同步字段
- `org_structure_node.path`
- `org_structure_node.level`
- 源删除、源状态等内部字段
- 人员 `mobile`、`email`
- 同步记录的 `dependency_key`、完整 `error_message`

当前 `sys_table_field` 没有独立的详情隐藏标记。后续详情 API 必须继续通过 Response DTO 控制敏感字段，不得仅依赖元数据可见性。

## 7. 权限设计

### 7.1 菜单

新增一个父目录和六个功能菜单：

```text
组织主数据
├─ 法人架构
├─ 管理架构
├─ 人员与任职
├─ 岗位
├─ 同步批次
└─ 同步异常
```

菜单通过稳定 `name` 定位，分别绑定对应 `table_code`；管理架构、人员任职和同步批次通过现有 `option` 表达涉及的关联表。菜单指向后续已规划页面路径，本 Task 不创建页面。

### 7.2 按钮

仅登记只读镜像允许的动作：

- `query`
- `detail`
- `refresh`
- `bind_user`
- `unbind_user`
- `view_sync`
- `retry`
- `view_error`

未登记：

- `create`
- `update`
- `delete`

查询、树、options 等 API 权限以非页面按钮形式登记；详情、绑定、解绑、查看同步、重试、查看错误和刷新按页面动作登记。

### 7.3 super_admin 与 Casbin

Seed 复用现有功能权限链路：

1. `sys_menu`
2. `sys_menu_button`
3. `sys_role_menu`
4. `sys_role_menu_button`
5. Casbin policy

默认将组织目录、六个功能菜单及全部按钮授权给 `super_admin`。带 API path/method 的按钮同步生成 Casbin policy；通过完整 `ptype + role + path + method` 稳定键防重复。

这些 policy 是后续已评审组织 API 的功能权限基线，不表示本 Task 已实现对应 Controller 或接口。
