## 4. 法人查询能力

### 4.1 分页列表

`QueryLegalEntities`：

- 复用 `request.Basic`、`sys_table/sys_table_field` 查询元数据和 Repository 分页基线。
- 支持 `page`、`num`、`order`、`quick_query`、`expressions` 和 `filters`。
- QuickQuery 使用元数据允许的法人编码、名称、简称和统一社会信用代码。
- 返回统一 `data + total`。
- 只加载法人安全列表字段，不返回 source identity、source version 或同步内部字段。

### 4.2 详情

`GetLegalEntityDetail`：

- 仅接受内部 `legal_entity_id`。
- 非正整数返回统一参数错误。
- 不存在或在当前可见范围外返回稳定的 `org legal entity not found` 业务错误。
- 使用白名单 Response DTO，不直接返回 Model。

### 4.3 法人树

`GetLegalEntityTree`：

- 只使用 `org_legal_entity.parent_id`，不使用 `org_structure` 或 `org_structure_node`。
- 支持多根、`root_id` 子树和当前有效/停用/历史可见范围。
- 节点 `value` 和 `legal_entity_id` 都使用内部法人 ID。
- 对循环执行显式检测，返回稳定业务错误，禁止递归失控。
- 对当前可见集合中的孤儿节点提升为根节点，标记 `orphan=true`，并记录可诊断的内部 ID 警告；不伪造父子关系。

### 4.4 Options

`QueryLegalEntityOptions`：

- 支持关键字、分页和已选 ID 回显。
- 默认仅提供当前有效对象作为新选择项。
- 停用或历史已选对象可以按内部 ID 回显，并标记 `disabled=true`。
- `value` 只能是内部 `legal_entity_id`。
- `label` 使用平台统一的“编码 - 名称”展示格式。
- 不使用 `source_id` 或 `source_code` 作为持久化值。

## 5. API 与功能权限

| Method | Path | 能力 | Action |
| --- | --- | --- | --- |
| `POST` | `/admin/org/legal-entity/query` | 法人分页列表 | `query` |
| `GET` | `/admin/org/legal-entity/:id` | 法人详情 | `detail` |
| `POST` | `/admin/org/legal-entity/tree` | 法人树 | 复用 `query` |
| `POST` | `/admin/org/legal-entity/options` | 法人选项 | 复用 `query` |

路由注册到现有 `adminGroup`，沿用 Auth、Casbin、access log、request/trace context 和统一 Response 中间件。Casbin path/method 与 T002 Seed 完全一致，不按角色名称或 `super_admin` 硬编码，也没有新增数据权限。

## 6. 法人有效性规则

默认 `only_effective=true`。当前有效必须同时满足：

1. `status = enabled`。
2. `source_deleted = false`。
3. `valid_from` 为空或不晚于 `as_of_date`。
4. `valid_to` 为空或不早于 `as_of_date`。
5. 平台 GORM 软删除记录始终不返回，通用 `include_deleted` 不能绕过组织查询边界。

其他规则：

- `include_disabled=true` 仅显式放开状态过滤。
- `include_history=true` 仅显式放开源删除和有效期过滤。
- `only_effective=false` 是同时放开停用和历史对象的明确请求。
- `as_of_date` 使用 `YYYY-MM-DD`，按平台 `Asia/Shanghai` 时区解析。
- 有效期边界为包含关系。
- 一次同步失败不会改变法人业务有效性判断。

## 7. Service、Repository 与 DTO 边界

- Service 是有效性归一化、树组装、循环检测和业务错误翻译的唯一入口。
- Controller 仅做绑定、Validation、Service 调用和统一 Response。
- Repository 仅负责数据库谓词、分页和安全列加载，不包含业务权限或树规则。
- 只读查询不开启无意义事务。
- 其他模块后续应调用 `OrgService`，不得直接访问 Organization Repository。
- 列表、详情、树和 options DTO 均使用字段白名单。
- 所有默认响应均排除 `source_id`、`source_code`、`source_version`、`sync_status` 和 `last_error` 等内部字段。
