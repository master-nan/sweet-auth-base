## 2. Task 目标

本任务建立 Sweet Platform Repository 层最小开发基线，范围仅包括：

1. 明确 Repository 职责和依赖方向。
2. 保留并规范现有 `BasicRepository[T]` / `BasicRepositoryImpl[T]` 接口模式。
3. 统一基础读取方法的 context、soft-delete 和查询修饰器行为。
4. 统一动态字段参数的基础校验错误。
5. 保留 GORM 数据库错误供 Service 判断。
6. 补充行为测试和 Repository 依赖方向守卫。

本任务未修改 Service、Controller、DTO、业务模块、数据库结构、API、Frontend、Report、Organization、Integration 或 Data Permission。

## 4. Repository 审计结果

| 检查项 | 审计结论 | 本任务处理 |
| --- | --- | --- |
| 基础接口模式 | 大多数静态模型 Repository 通过领域接口嵌入 `BasicRepository[T]`，实现通过嵌入 `BasicRepositoryImpl[T]` 复用基础能力 | 保留该模式，不建立第二套 Repository |
| 动态表例外 | `GeneralizationRepository` 面向运行时动态表，无法使用静态泛型模型，属于合理例外 | 保留，不改业务查询 |
| Repository 职责 | 当前 Repository 未发现反向调用 Service/Controller，但此前没有自动守卫 | 新增依赖方向测试 |
| 基础 CRUD | `Create`、`Update`、Delete、Find 能力已集中存在 | 保留现有签名，不批量改业务调用 |
| 分页 | 标准静态列表主要复用 `PaginateAndCountAsync`；动态表使用自己的分页查询 | 保留现有分页入口并统一查询选项 |
| Context | `WithContext` 只在部分基础读取路径生效，`QueryWhere` 未继承 context；公开接口仍使用项目既有 `*gin.Context` | 统一基础读取和分页的 context 应用；不在本任务进行全仓签名迁移 |
| `WithUnscoped` | Find 方法生效，但分页忽略该修饰器，行为不一致 | 修复分页行为 |
| `WithSelect` / `WithOmit` | 分页生效，但 Find 方法忽略，行为不一致 | 统一应用到基础读取 |
| 链式修饰器 | 浅复制切片可能导致同源 Repository clone 共享底层数组 | 改为独立复制选项切片 |
| 动态字段方法 | `FindByField`、`DeleteByField` 等通过字符串拼接字段名，未统一校验 | 限制为合法字段标识符并返回稳定错误 |
| 错误返回 | 基础方法通常原样返回 GORM error；非切片参数使用临时字符串错误 | 保留 GORM error；新增可用 `errors.Is` 判断的参数错误 |
| 业务判断和权限判断 | 未发现 `backend/repository` 直接导入 Service/Controller | 自动测试防止未来反向依赖 |
| 事务 | `ExecuteTx` 已由 Service 调用并使用 GORM transaction | 不改变事务边界 |

## 5. Repository 基线

### 5.1 允许职责

- 数据库访问。
- 查询条件组合。
- 基础 CRUD。
- 列表分页与总数查询。
- 预加载、字段选择、软删除查询。
- 原子状态更新和领域明确的持久化查询。

### 5.2 禁止职责

- 业务规则判断。
- 功能权限或数据权限决策。
- 调用 Service 或 Controller。
- 跨领域业务编排。
- 外部 HTTP 调用。
- API 错误和响应结构转换。

### 5.3 Interface 模式

1. 有静态模型的领域 Repository 继续定义在 `backend/repository/`。
2. 领域接口优先嵌入 `BasicRepository[T]`，只追加领域特有数据访问方法。
3. 实现在 `backend/repository/impl/`，优先嵌入 `BasicRepositoryImpl[T]`。
4. 动态表等确实无法绑定静态模型的 Repository 可以保留专用接口，但不得复制另一套通用 CRUD 基线。
5. 本任务不批量改写全部历史 Repository。

### 5.4 错误返回

1. 数据库错误原样返回给 Service，保留 `errors.Is(err, gorm.ErrRecordNotFound)` 等判断能力。
2. Repository 不转换为 HTTP 状态或 `AdminError`。
3. 动态字段非法时返回 `repository.ErrInvalidField`。
4. `FindListByFieldIn` 参数不是数组或切片时返回 `repository.ErrInvalidFieldValues`。

### 5.5 分页

1. 静态模型标准列表继续使用 `PaginateAndCountAsync`。
2. 分页继续使用 `request.Basic` 和 `model.SysTable`。
3. 查询、数据范围、分页和 count 继续沿用现有 `repository/util`。
4. `WithContext`、`WithUnscoped`、`WithSelect`、`WithOmit`、`WithPreload` 在基础分页和读取方法中保持一致。

### 5.6 Context

1. 当前公开接口继续兼容项目既有 `*gin.Context`，避免本任务要求修改 Service 和测试替身。
2. 读取链使用 `WithContext(ctx)`。
3. 写入和显式事务使用传入的 `*gorm.DB`，调用方通过 `DBWithContext(ctx)` 或 `ExecuteTx(ctx, fn)` 注入 context。
4. `WithContext` 返回独立 clone，不修改共享 Repository 实例。
5. 将公开签名迁移到标准库 `context.Context` 涉及 Service、Model hook 和测试替身，超出本任务范围。

## 7. 修改内容

1. 为 `BasicRepository` 增加职责、禁止事项和错误传递说明。
2. 增加稳定参数错误：
   - `ErrInvalidField`
   - `ErrInvalidFieldValues`
3. 增加统一 `baseQuery()`，让 context 和 `WithUnscoped` 应用于所有基础读取和分页路径。
4. 增加统一 `applyReadOptions()`，让 select、omit、preload 在 Find 和分页路径表现一致。
5. 增加 `clone()` 深复制修饰器切片，避免 sibling clone 互相污染。
6. 为动态字段型查询和删除方法增加字段标识符校验。
7. 保留 GORM 错误，不在 Repository 转换 API 错误。
8. 新增 Repository 依赖方向守卫，禁止生产代码导入 `backend/service` 或 `backend/controller`。

## 10. 未处理问题

1. `BasicRepository` 公开 context 类型仍为 `*gin.Context`。迁移到标准库 `context.Context` 需要同步调整 Service、Model hook 和测试替身，应另设兼容性任务。
2. `QueryWhere(string)` 仍接受原始条件字符串，当前存在历史调用。替换为参数化专用方法需要修改 Service，不属于本任务。
3. `ApplicationRepository.IsAppKeyExists` 和 `IsAppSecretExists` 只返回 bool，无法区分“不存在”和“数据库错误”。本任务按“不大规模重构业务 Repository”约束仅记录。
4. 一部分领域 Repository 自定义读取方法尚未显式接收 context。批量迁移会影响 Service 接口，留待独立任务。
5. `PaginateAndCountAsync` 仍保留现有并发 count/data 查询策略。本任务只统一行为，没有调整性能模型。
6. `Update` 继续使用现有 mapstructure 转换策略。本任务未改变字段更新语义。
7. `backend/repository/impl/sys_role_menu_button_impl.go` 的历史未提交改动仍保留，未进入本任务。
