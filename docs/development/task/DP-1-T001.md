# DP-1-T001 Data Permission Domain Models

## 1. 任务目标

基于 `docs/development/design/Data-Permission-P0-Revision.md` 建立新数据权限领域模型基线。

本 Task 仅新增 Model、模型结构测试和受控枚举约束准备，不实现 Repository、Service、Controller、Resolver、Filter Adapter、Migration 或 Seed。

## 2. 开始前工作区状态

任务开始前工作区已有 Report、Frontend、design 和相关文档的未提交改动。本 Task 未覆盖、回滚、暂存或提交这些历史改动。

## 3. 模型范围

| Model | 物理表名 | 领域职责 |
| --- | --- | --- |
| `DataDimensionDefinition` | `sys_data_dimension_definition` | 定义稳定数据维度及 Provider |
| `DataResource` | `sys_data_resource` | 定义受保护的低代码表、业务服务或 Report 资源 |
| `DataResourceOperation` | `sys_data_resource_operation` | 定义资源支持的数据权限操作 |
| `DataOwnershipField` | `sys_data_ownership_field` | 定义资源归属字段与维度的绑定 |
| `DataPolicy` | `sys_data_policy` | 定义不绑定主体和资源的可复用策略 |
| `DataPolicyRule` | `sys_data_policy_rule` | 定义 rule_set 策略中的结构化规则 |
| `DataGrant` | `sys_data_grant` | 将策略授予 role 或 user 的资源操作 |

全部模型复用 `model.Basic`，沿用平台审计字段、状态字段和软删除方式，没有新增第二套删除或状态模型。

## 4. 字段与关系边界

1. `DataPolicyRule.dimension_id` 为必填 `bigint` 字段。
2. `DataOwnershipField.binding_type` 仅预留 `metadata_field`、`registered_field`。
3. `DataOwnershipField` 不包含 `report_source`。
4. `DataGrant.subject_type` 仅预留 `role`、`user`。
5. `DataResource` 不使用 `menu_id` 作为资源主键或关系字段。
6. 所有模型均不包含 `organization_id`、`structure_node_id`、SQL 字段或动态表达式字段。
7. 关系只保存 `resource_id`、`dimension_id`、`policy_id` 等必要标识，不配置自动 Preload 关系。
8. `specified_values` 使用 JSONB 数组载体；类型、数量、Provider 有效性及条件必填规则留给后续 Service 实现。
9. `DataScopeResult` 不属于本 Task，未实现。

## 5. 枚举约束准备

Model 中为最终 P0 受控值提供常量和 GORM check 约束声明，覆盖：

- Dimension category 和 value type。
- Resource type 和 operation。
- Ownership binding type 和 value type。
- Policy type。
- Rule scope source、relation 和 operator。
- Grant subject type 和 operation。

这些声明用于后续 Migration 和 Service 校验保持同源；本 Task 未注册或执行 Data Permission Migration，不会改变现有数据库。
