## 5. 统一请求协议

新增公共请求基类 `OrgSelectorOptionsReq`：

| 字段 | 语义 |
| --- | --- |
| `page` | 当前分页页码 |
| `num` | 单页数量，受平台最大分页限制 |
| `keyword` | 编码或名称远程搜索关键字 |
| `selected_ids` | 已持久化内部 ID 的批量回显列表，最多 100 个 |
| `only_effective` | 默认 `true`，限制新选择项为当前有效对象 |
| `include_disabled` | 显式包含停用对象 |
| `include_history` | 显式包含历史对象 |
| `as_of_date` | 按指定日期判断有效性 |

四类对象 Request DTO 统一嵌入该协议，并保留各自必要过滤字段：

- 法人主体：无额外对象过滤。
- 管理组织：`legal_entity_id`、`structure_id`。
- 企业人员：`legal_entity_id`、`org_unit_id`、`position_id`。
- 岗位：`legal_entity_id`、`org_unit_id`。

JSON 字段保持扁平，调用方不感知 Go DTO 的组合方式。

## 6. 统一响应协议

Service 统一返回 `OrgSelectorOptionsRes`：

```text
Items
  - value
  - label
  - disabled
  - code
  - name
Total
```

其中：

- `value` 始终是平台内部整数 ID。
- `label` 使用“编码 - 名称”格式。
- `disabled=true` 表示仅用于已保存值回显，不可作为新选择项。
- `code/name` 是展示辅助字段，不是持久化值。
- `total` 只统计正常分页候选，不把额外回显的 `selected_ids` 重复计入。

为遵守 Platform Foundation 冻结的 Response 基线，Controller 将 `Items` 映射到平台外层 `response.data`，将 `Total` 映射到 `response.total`，不新增第二套 API envelope。

## 7. ID 语义

| API | `value` |
| --- | --- |
| LegalEntityOptions | `legal_entity_id` |
| OrgUnitOptions | `org_unit_id` |
| EmployeeOptions | `employee_id` |
| PositionOptions | `position_id` |

禁止使用名称、`source_id`、`source_code`、`structure_node_id` 或 `user_id` 作为上述四类业务选择器的持久化值。

管理组织若按 `structure_id` 过滤，仍通过 `org_structure_node` 找到实际引用的 `org_unit`；返回值保持 `org_unit_id`，不会变成节点 ID。

## 8. 历史回显规则

1. 默认 `only_effective=true`，停用、离职、过期或源删除对象不会进入新选择候选。
2. `selected_ids` 可批量回显当前分页和 keyword 未命中的已保存对象。
3. 历史或停用对象回显时强制 `disabled=true`。
4. 当前仍有效但仅因 keyword 或分页未命中的 selected ID 可以正常回显。
5. 不存在或平台软删除的 ID 不伪造选项。
6. Service 不推断权威源未提供的历史。

## 9. API 与权限

| Method | Path | Action | `value` 语义 |
| --- | --- | --- | --- |
| POST | `/admin/org/legal-entity/options` | `query` | `legal_entity_id` |
| POST | `/admin/org/unit/options` | `query` | `org_unit_id` |
| POST | `/admin/org/employee/options` | `query` | `employee_id` |
| POST | `/admin/org/position/options` | `query` | `position_id` |

四个接口复用各自菜单的 `query` 权限。没有新增 action、权限模型、角色判断或数据权限；Seed 测试补充验证四条 path/method/action 与 Casbin policy 的幂等一致性。

## 10. 性能边界

1. 正常候选始终分页，禁止无上限加载全表。
2. `num` 受平台 `ValidatePagination` 最大值保护。
3. `selected_ids` 最多 100 个。
4. 正常候选查询使用 count + page 两次数据库查询。
5. selected ID 使用一次 `IN` 批量查询。
6. 四类 Options 在包含 selected 回显时均保持三次固定查询，不随返回项数量增长。
7. 不在应用层读取全表后分页或逐项查询。
8. 管理组织带 `structure_id` 时允许增加一次架构有效性校验，但不会形成节点或组织 N+1。
