## 5. Repository 设计

新增九类 Repository：

1. `OrgLegalEntityRepository`
2. `OrgUnitRepository`
3. `OrgStructureRepository`
4. `OrgStructureNodeRepository`
5. `OrgPositionRepository`
6. `OrgEmployeeRepository`
7. `OrgAssignmentRepository`
8. `OrgSyncBatchRepository`
9. `OrgSyncRecordRepository`

统一能力：

- 使用 `request.Basic`。
- 使用 `PaginateAndCountAsync`。
- `sys_table/sys_table_field` 仍是唯一查询元数据来源，不在 Repository 建立第二套字段元数据。
- Repository 仅保留元数据已标记为列表、关键字、高级查询、排序或主键的字段，隐藏字段不能借由通用 expressions/filters 查询。
- typed query 字段复制到新的 `Filters`，不修改调用方 DTO。
- 普通列表通过 `WithSelect` 限制返回列。
- `source_system_code + source_id` 使用专用稳定定位方法，不依赖数据库自增 ID。
- 不在 Repository 默认增加“当前有效”业务规则，该规则属于后续 Organization Query Service。

## 6. 字段更新边界

### 6.1 源字段更新

镜像同步必须调用 `UpdateSourceFields`。每个模型使用独立白名单，允许更新源业务字段、源状态和同步运行字段；禁止修改：

- `user_id`
- `local_note`
- `local_tags`
- `display_order`
- `local_handling_status`
- `model.Basic` 系统字段
- 稳定源身份 `source_system_code + source_id`

### 6.2 平台扩展字段更新

平台操作必须调用 `UpdatePlatformFields`。V1 白名单仅包含相应模型已评审的平台扩展字段：

- 法人/管理组织：`local_note`、`local_tags`、`display_order`、`local_handling_status`
- 岗位：`local_note`
- 人员：`user_id`、`local_note`、`local_tags`

白名单外字段在执行 SQL 前返回 `ErrOrganizationFieldBoundary`。实现使用明确列集合执行 `Updates`，不使用整行 `Save`。

`BasicRepository.Update` 因平台兼容仍存在；后续 Organization Service 必须使用上述组织专用入口，不得用泛型整行更新绕过字段边界。

## 7. DTO 与敏感字段边界

### 7.1 Query DTO

新增法人、管理组织、架构、架构节点、人员、岗位、任职、同步批次和同步记录查询 DTO。

查询 DTO：

- 支持分页、排序、QuickQuery 和 AdvancedQuery 的现有 `request.Basic`。
- 对状态、类型、关联 ID 提供明确字段和校验。
- 不提供 `source_id`、`source_version`、联系方式、树 `path`、错误消息或依赖键查询字段。

### 7.2 Response DTO

Model 只在 Repository/Service 内部流转，禁止直接作为 Controller 响应。

默认列表和详情 DTO 不返回：

- `source_system_code`
- `source_id`
- `source_version`
- `sync_status`
- `last_error`
- 树物化路径 `path`
- 原始手机号和邮箱
- 同步错误消息和依赖键

特殊边界：

- `org_employee.user_id` 在 DTO 中使用 Go 字段 `BoundUserId`，JSON 保持 `user_id`，明确表示“绑定账号”，不是 `employee_id`。
- 人员列表不返回联系方式；人员详情只返回 `mobile_masked` 和 `email_masked`。
- `path` / `level` 属于 `org_structure_node`，不属于 `org_unit`。默认节点 DTO隐藏内部 `path`，仅保留可显示的 `level`。
- 同步列表/详情仅返回 `has_error` 和错误分类字段。
- 原始 `error_summary`、`error_message`、`dependency_key` 只存在于独立 `view_error` 响应 DTO，后续 Controller 必须绑定对应功能权限。
- 同步记录保留非敏感 `source_code` 作为业务排障定位值，但不返回原始 `source_id`。
