## 4. 接口实现

### 4.1 GetEmployeeByUser

输入：

- `user_id`

返回：

- `user_id`
- `employee_id`
- `binding_status`

规则：

1. 使用现有账号摘要 Repository 确认账号存在。
2. 账号不存在返回现有稳定错误 `ErrOrgUserNotFound`。
3. 账号存在但无员工绑定时成功返回 `unbound`。
4. 已绑定时只返回 `employee_id`，不返回用户名、密码、Token、角色或权限。
5. 不按用户名、姓名、手机号或邮箱推断绑定。

### 4.2 GetEffectiveAssignments

输入：

- `employee_id`
- `as_of_date`

返回每条有效任职的最小事实：

- `assignment_id`
- `employee_id`
- `legal_entity_id`
- `org_unit_id`
- `position_id`
- `valid_from`
- `valid_to`

规则：

1. `as_of_date` 必填，使用平台时区解析。
2. 校验员工存在且在指定日期有效。
3. Repository 按员工、状态、源删除标记和有效期查询。
4. 返回全部有效任职，不筛选 `is_primary`，不选择第一条。
5. 排除历史、未来、停用和源删除任职。
6. `valid_from` 和 `valid_to` 当日均包含。
7. 批量校验引用法人和管理组织存在且有效。
8. 按法人、组织、岗位和任职 ID 稳定排序。
9. 超过现有任职摘要上限时返回稳定错误，不截断。

### 4.3 GetEmployeeEffectiveOrganizationScope

输入：

- `employee_id`
- `as_of_date`

返回：

- `employee_id`
- `as_of_date`
- `scope_status`
- `assignment_count`
- `legal_entity_ids`
- `org_unit_ids`

规则：

1. 复用 `GetEffectiveAssignments`。
2. 法人和组织 ID 分别去重。
3. ID 按升序返回。
4. 无有效任职返回 `scope_status=empty` 和非空空数组。
5. 有有效任职返回 `scope_status=resolved`。
6. 响应不存在 `all` 或其他放开范围字段。

## 5. Repository 变更

`OrgAssignmentRepository` 新增最小只读方法：

- `ListEffectiveByEmployee`

该方法只负责：

- 按 `employee_id` 查询。
- 应用任职状态、源删除和有效期条件。
- 设置结果上限。
- 提供稳定数据库排序。

业务有效性、引用对象校验、错误转换和范围聚合仍位于 Service。

## 6. DTO 边界

新增独立白名单 DTO：

- `OrgEmployeeContextRes`
- `OrgEffectiveAssignmentRes`
- `OrgEffectiveOrganizationScopeRes`

DTO 不包含：

- 用户名、密码、Token。
- 角色、菜单、按钮、Casbin Policy。
- `source_id`、`source_code`、`source_version`。
- 同步状态和同步错误。
- 权限策略、SQL 或全量范围标记。

## 7. 错误边界

复用现有 AdminError/Organization 错误体系，并补充：

- `ErrOrgEmployeeInactive`
- `ErrOrgLegalEntityInactive`
- `ErrOrgUnitInactive`

账号不存在、员工不存在和引用对象不存在继续复用既有稳定错误。参数错误使用统一参数错误类型，不使用原始字符串错误作业务分支。

## 8. 边界确认

本实现：

- 只提供组织事实。
- 不访问任何 Data Permission 表或 Service。
- 不判断角色、菜单、按钮或 Casbin。
- 不生成 SQL 权限过滤条件。
- 不修改 Organization Model。
- 不新增数据库表、字段、Migration 或 Seed。
- 不新增 Controller、Router、API 或页面。
- 不实现树关系 Provider；树接口保留给后续独立 Task。
