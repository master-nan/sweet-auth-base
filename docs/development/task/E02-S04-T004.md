## 4. 表单渲染规则

当 `resolveOrganizationSelectorConfig(field)` 返回有效配置时，`DynamicFormDialog` 自动渲染现有 `OrganizationSelect`。

支持：

| selector_type | 表单值语义 |
| --- | --- |
| `legal_entity` | `legal_entity_id` |
| `org_unit` | `org_unit_id` |
| `employee` | `employee_id` |
| `position` | `position_id` |

向组件传递：

- `modelValue`
- `selectorType`
- `multiple`
- `includeHistory`
- `disabled`
- 字段 label、clearable、rules 和 hint

`readonly` 与 metadata 的 `disabled` 合并；任一为 true 时选择器不可编辑。

## 5. 控件优先级与兼容

普通业务字段的选择器分支在原有控件推断之前执行：

```text
selector_type
  > 原有字典/关联/field_type 控件链路
```

为保证“无 selector 配置行为完全不变”，原有字典、linkage 和普通 field type 之间的内部处理顺序未调整。

当 selector metadata 同时带有旧 `dict_code` 或 linkage 配置时：

1. 只渲染 `OrganizationSelect`。
2. 不预加载该字段字典。
3. 不请求该字段旧 relation/cascader options。

没有 selector 配置时，文本、数字、日期、字典、关联、文件、富文本及其他既有控件继续使用原实现。

## 6. 表单值边界

选择器值在写入 `formData` 前统一归一化：

1. 单选只接受正整数内部 ID，空值为 `null`。
2. 多选只接受正整数内部 ID 数组，并自动去重。
3. 合法数字字符串转换为 number。
4. label、name、对象和其他非 ID 值不会进入提交数据。
5. 新建单选默认 `null`，新建多选默认空数组。
6. 编辑数据会在初始化时执行同一归一化。

`employee` selector 的值始终是 `employee_id`，不会使用 `user_id` 代替。

## 7. 历史值回显

`DynamicFormDialog` 将现有 model value 和 `includeHistory` 传给 `OrganizationSelect`。现有组件会把当前 ID 纳入 `selected_ids` 回显请求；后端返回的停用或历史对象保持 `disabled=true`，可显示但不可重新选择。

本 Task 不重复实现 Options 请求或历史状态逻辑。
