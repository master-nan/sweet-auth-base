## 2. 任务目标

本 Task 在前置四类 Organization Options API 之上实现统一的前端远程选择器基础能力：

1. 提供共享 `OrganizationSelect` 组件。
2. 每个组件实例通过必填 `selectorType` 固定为法人、管理组织、人员或岗位之一。
3. 统一远程搜索、分页上限、loading、empty、error、disabled 和历史值回显行为。
4. 统一使用 Options API 返回的内部 ID，不在前端保存名称或源系统 ID。
5. 增加可执行的前端组件和 API 自动化测试。

本组件共享实现代码，但不会在同一实例中混合法人、管理组织、人员和岗位选项；`selectorType` 一经传入即决定唯一 API 和唯一 ID 语义。

## 4. 组件设计

### 4.1 单实例单类型

`OrganizationSelect` 支持以下 `selectorType`：

| selectorType | API | value 语义 |
| --- | --- | --- |
| `legal_entity` | `/admin/org/legal-entity/options` | `legal_entity_id` |
| `org_unit` | `/admin/org/unit/options` | `org_unit_id` |
| `employee` | `/admin/org/employee/options` | `employee_id` |
| `position` | `/admin/org/position/options` | `position_id` |

组件只复用渲染和请求流程，不允许一个实例同时加载多种对象，也不会在运行时把 `user_id`、`source_id`、名称或 `structure_node_id` 作为 value。

### 4.2 Props 与事件

支持 Props：

- `modelValue`
- `selectorType`
- `multiple`
- `disabled`
- `clearable`
- `includeHistory`
- `selectedIds`
- `keyword`

支持事件：

- `update:modelValue`
- `change`

单选值为正整数 ID 或 `null`，多选值为正整数 ID 数组。当前 model 中的 ID 优先进入回显请求，回显 ID 去重并遵守后端最多 100 个的协议限制。

### 4.3 平台组件复用

组件复用 `SweetSelect`，最终由 Quasar `q-select` 提供交互，不创建第二套 Select UI。组件保持平台现有 dense、outlined、clear icon 和菜单样式，并透传现有属性及插槽。

### 4.4 远程搜索与状态

1. 初次加载和关键字搜索均调用后端 Options API。
2. `page=1`、`num=50`，不在前端加载全表后过滤。
3. `input-debounce=300`，并使用请求序号避免旧响应覆盖新搜索结果。
4. Options 请求跳过全局 loading，只显示选择器自身 loading。
5. `/options` POST 被视为查询请求，不显示写操作成功提示。
6. 空结果显示“暂无可选数据”，请求失败显示“选项加载失败”。

### 4.5 历史值回显

1. 当前 `modelValue` 与 `selectedIds` 合并后批量发送。
2. 停用或历史对象由后端返回 `disabled=true`。
3. disabled 选项可以显示已保存值，但不能作为新选择项。
4. 默认仍以 `only_effective=true` 加载可选数据。

## 5. API 边界

新增 `frontend/src/api/services/org.ts`：

1. 集中维护四类 Options endpoint。
2. 使用现有 `boot/axios` 实例和统一 Response envelope。
3. 通过 `X-Skip-Global-Loading` 避免远程输入时触发整页 loading。
4. 对 option value 做正整数校验，异常 value 不进入组件。
5. Response 只包含 `value`、`label`、`code`、`name`、`disabled` 和 `total`。

人员选项不会展示密码、token、权限或完整联系方式；岗位选项不包含角色信息。
