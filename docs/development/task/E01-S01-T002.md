## 4. Seed 审计结果

| 检查项 | 结论 | 本任务处理 |
| --- | --- | --- |
| 重复执行是否产生重复记录 | 大部分基础 Seed 已通过业务键或 `OnConflict DoNothing` 幂等；缺少完整回归测试 | 新增完整两轮 Seed 数据结果测试 |
| 是否依赖固定数据库自增 ID | 部分历史基础 Seed 带固定初始 ID，但已通过业务键查询和 `seedPrimaryId` 兜底 | 保留现状，不重构 ID 策略 |
| 是否通过稳定业务键定位已有记录 | 菜单、按钮、表、字段、关系、按钮模板、Casbin 已满足；字典项原先仅按 `item_code` 全局定位 | 修复字典项定位为 `dict_id + item_code` |
| 更新已有记录是否误覆盖用户配置 | `seedConfigure` 和字典名称/字典项名称不覆盖用户维护值；菜单、按钮、元数据会修复 Seed 拥有字段 | 新增测试覆盖配置和字典用户维护字段不被覆盖 |
| 菜单和按钮识别 | 菜单按 `name`，按钮按 `menu_id + code` | 新增重复组断言 |
| `sys_table` 识别 | 按 `table_code`，会恢复系统基础表元数据 | 新增重复组断言 |
| `sys_table_field` 识别 | 按 `table_id + field_code`，会修复系统字段元数据 | 新增重复组断言 |
| 字典识别 | 按 `dict_code` | 新增重复组断言 |
| 字典项识别 | 原先按 `item_code`，存在跨字典误判风险 | 改为 `dict_id + item_code`，并断言 `dict_id + item_code`、`dict_id + item_value` 不重复 |
| Casbin policy | 按 `ptype + v0 + v1 + v2` 查询后创建 | 新增重复组断言 |
| Seed 执行顺序 | T001 已固定 `platformSeedSteps()` 顺序 | 保留并继续使用现有顺序测试 |
| 删除、停用或历史配置是否被错误恢复 | `sys_table`、`sys_table_field`、系统菜单按钮等平台基线会被 Seed 修复为启用；这是当前平台基础 Seed 设计 | 本任务不改变该策略，后续如需“用户停用保护”应单独设计 |
| 非 Seed 拥有字段是否被重复执行修改 | 主要风险在通用 Seed 不区分字段所有权 | 本任务最小覆盖 `sys_configure`、`sys_dict`、`sys_dict_item` 用户维护字段不被覆盖 |

## 6. 幂等策略

本任务不建立第二套 Seed 注册机制，继续复用：

- `platformSeedSteps()`
- `seedAllData()`
- `runSeedSteps()`

本任务新增和确认的幂等策略：

1. 字典通过 `dict_code` 定位。
2. 字典项通过 `dict_id + item_code` 定位。
3. 菜单通过 `name` 定位。
4. 菜单按钮通过 `menu_id + code` 定位。
5. 低代码按钮模板通过 `scene + code_suffix` 定位。
6. `sys_table` 通过 `table_code` 定位。
7. `sys_table_field` 通过 `table_id + field_code` 定位。
8. 角色菜单、角色按钮通过复合主键和 `OnConflict DoNothing` 防重复。
9. Casbin policy 通过 `ptype + v0 + v1 + v2` 定位。
10. 重复执行 Seed 不新增重复记录，不改变第一轮生成对象的稳定业务键与 ID 对应关系。

- `TestPlatformSeedStepsAreIdempotentForFoundationData`
