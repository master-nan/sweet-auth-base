## 2. 任务目标与账号绑定语义

本 Task 只实现 `org_employee.user_id` 的绑定、解绑和安全状态回显。该字段表示企业人员与当前 Sweet Platform 应用实例登录账号之间的可空一对一关系：

- 一个企业人员最多绑定一个 `sys_user`。
- 一个 `sys_user` 最多绑定一个企业人员。
- 企业人员可以没有平台账号。
- 平台账号也可以没有企业人员。
- 绑定必须显式提交 `employee_id` 和 `user_id`。

该关系不是集团统一身份、外部系统账号映射或账号同步能力。本 Task 不使用姓名、手机号、邮箱、用户名等属性推断关系，不创建账号，不分配角色、菜单或数据权限。

## 3. 为什么不新增关系表

P1B 评审和 Organization Domain Review 已确认 V1 保持 `org_employee.user_id`：

1. V1 只描述当前应用实例内的 `1:0..1` 账号绑定，不需要多账号类型、多实例映射或绑定历史。
2. `org_employee.user_id` 已明确属于平台扩展字段，不会被组织源字段同步覆盖。
3. 模型已有 `user_id IS NOT NULL` 条件唯一索引 `uni_org_employee_user`，能够为并发绑定提供数据库兜底。
4. 新增关系表会扩大已评审模型边界，且当前不存在可复用收益。

未来若出现多身份源、绑定历史或多应用实例映射，应重新评审独立关系模型；本 Task 不提前实现。

## 5. 绑定与解绑规则

### 5.1 绑定

Service 在同一事务中：

1. 按内部 `employee_id` 锁定并确认企业人员存在。
2. 确认企业人员当前未绑定账号。
3. 按内部 `user_id` 锁定并确认平台账号存在。
4. 确认账号未绑定其他企业人员，包括软删除员工仍受唯一关系约束的情况。
5. 仅通过 Organization Repository 的平台字段白名单更新 `user_id`。
6. 写入包含旧值和新值的成功审计。

数据库条件唯一索引是并发安全最终防线。并发冲突统一转换为稳定业务错误，不向调用方泄露数据库错误。

### 5.2 解绑

Service 在同一事务中：

1. 按内部 `employee_id` 锁定并确认企业人员存在。
2. 若已绑定，则仅将 `user_id` 清空。
3. 写入包含旧值和新值的成功审计。

对已经未绑定的企业人员执行解绑采用幂等成功语义，并保留本次操作审计。

## 6. 事务与 Repository 边界

- 事务入口只在 `OrgService`，Repository 不开启事务。
- 绑定查询使用 `FOR UPDATE` 锁定企业人员和账号；数据库唯一约束负责最终并发兜底。
- Organization Repository 只负责受控数据库访问，不判断权限、不调用 Service。
- `UpdatePlatformFields` 继续使用既有白名单，仅允许更新平台扩展字段。
- 审计与 `org_employee.user_id` 更新使用同一个数据库事务。
- 审计写入失败时绑定或解绑整体回滚。
- 成功事务审计提交后，访问日志中间件不再重复写入第二条成功记录；失败请求仍由请求日志记录并保留 trace/request 关联。

## 7. 权限设计

本 Task 复用 E02-S01-T002 已存在的权限 Seed，不新增权限模型或角色：

| Method | Path | Action | 用途 |
| --- | --- | --- | --- |
| POST | `/admin/org/employee/:id/bind-user` | `bind_user` | 显式绑定企业人员与平台账号 |
| POST | `/admin/org/employee/:id/unbind-user` | `unbind_user` | 解除当前平台账号绑定 |

`sys_menu_button`、`sys_role_menu_button` 和 Casbin policy 已由现有幂等 Seed 建立，默认授权沿用平台现有 `super_admin` Seed 流程。Controller 不硬编码角色名称，接口访问继续由 Casbin 控制。

## 8. 审计设计

绑定和解绑成功审计复用现有 `access_log` 与 Logger/Audit Baseline，至少保存：

- 操作人 `user_id/user_name`
- `request_id/trace_id`
- action：`bind_user` 或 `unbind_user`
- resource：`org_employee`
- `employee_id`
- `user_id` 旧值与新值
- 成功结果

审计不保存账号密码、Token、角色、权限或其他安全字段。绑定或解绑失败时，事务审计不提交，由请求日志记录安全错误结果。

## 9. DTO 与安全边界

请求 DTO：

- `OrgEmployeeBindUserReq`：路由中的 `employee_id` 与正文中的 `user_id`
- `OrgEmployeeUnbindUserReq`：路由中的 `employee_id`

响应 DTO 只允许：

- `employee_id`
- 可空 `user_id`
- `binding_status`
- 可选账号摘要：`user_id`、`user_name`

禁止返回完整 `SysUser` Model、密码、Token、角色、权限、登录安全状态及 Organization 源内部字段。现有员工详情的账号绑定摘要继续沿用同一白名单。
