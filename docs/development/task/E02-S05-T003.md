## 4. Provider 接口

### 4.1 GetOrgAncestors

输入：

- `structure_code`
- `org_unit_id`
- `as_of_date`
- `include_self`

返回指定组织的有效祖先集合。结果只包含 `org_unit_id` 和 `distance`，按距离、组织 ID 稳定升序排列。

### 4.2 GetOrgDescendants

输入与祖先查询一致，返回指定组织的全部有效后代。超过现有组织树节点上限时返回稳定错误，不返回截断集合。

### 4.3 IsOrgDescendant

输入：

- `structure_code`
- `ancestor_org_unit_id`
- `descendant_org_unit_id`
- `as_of_date`
- `include_self`

正常无关系返回 `is_descendant=false`；同一组织仅在 `include_self=true` 时返回距离 `0`。不存在、失效、孤儿或循环数据返回稳定错误。

## 5. 复用与算法边界

本实现没有新增第二套数据库组织树算法：

1. 现有 `GetStructureOrgTree` 的读取主体抽取为内部 `getStructureOrgTreeForRead`。
2. 管理端树查询继续通过原入口完成参数标准化，行为保持不变。
3. Permission Provider 使用显式日期调用同一读取主体，复用：
   - 架构有效性校验；
   - 节点和组织有效性过滤；
   - 节点批量查询；
   - 循环检测；
   - 孤儿标记；
   - 节点数量上限。
4. Provider 仅将已经校验的树结果转换为内部关系索引，用于祖先、后代和关系判断。
5. Provider 对孤儿数据安全失败；同一有效架构内同一组织对应多个节点时返回明确歧义错误。

关系响应不暴露 `structure_node_id`、`parent_node_id`、`path` 或源系统字段。

## 6. 日期和架构规则

1. `structure_code` 必填，不读取默认架构，不使用 `is_default` 自动选择。
2. `as_of_date` 必填，格式固定为 `YYYY-MM-DD`。
3. Provider 不读取 `time.Now()` 补默认日期。
4. 日期判断使用平台时区，并同时校验架构、节点和组织单元在指定日期的有效性。
5. 不同管理架构独立计算，禁止跨架构复用父子关系。

## 7. 错误边界

复用现有 Organization/AdminError 体系，并增加：

- `ErrOrgStructureMembershipNotFound`：组织单元不在指定管理架构中。
- `ErrOrgStructureMembershipAmbiguous`：同一有效管理架构中存在多个该组织节点，无法给出唯一组织关系。

继续复用：

- 架构不存在或无效；
- 组织不存在或无效；
- 节点缺失；
- 组织树循环；
- 组织树超限；
- 参数错误。

错误判断不依赖错误字符串。
