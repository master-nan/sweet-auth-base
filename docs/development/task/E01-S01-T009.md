## 2. 任务目标与边界

本任务建立未来平台模块共同遵循的最小测试基线：

1. 固定 Unit、Repository、Service、Permission、Seed 和 Integration Test 的职责。
2. 提供轻量公共测试 helper，减少数据库、fixture、HTTP mock 和权限断言的重复实现。
3. 明确内存 SQLite 与生产 PostgreSQL 的覆盖边界。
4. 保留标准库 `testing`、手写 fake/spy 和现有依赖，不引入大型测试框架。
5. 通过 Platform Foundation 的事务和权限测试验证公共 helper。

本任务不批量迁移历史测试，不修改业务逻辑、数据库结构、Migration、Seed、API 或前端，也不开发 Organization、Integration、Data Permission 或 Report。

### 4.2 存在的重复与风险

| 问题 | 风险 | 本任务处理 |
| --- | --- | --- |
| 多处直接 `gorm.Open(sqlite.Open(...))` | DSN、命名策略、日志、连接数和清理不一致 | 新增统一 `OpenSQLite` |
| 部分测试使用共享 `:memory:`，部分使用命名内存库 | 多连接或未来并行时行为不稳定 | 每个调用生成唯一命名库，单连接并自动关闭 |
| SQLite 配置与生产 SingularTable/NowFunc 不一致 | 测试表名和时间语义偏离生产 | helper 对齐现有 GORM 基础配置 |
| fixture 写入重复检查错误 | 样板代码多，错误信息不统一 | 新增 `MustCreate` |
| 回滚隔离各自实现 | 测试数据可能互相污染 | 新增 `WithRollback` |
| Seed 两次执行比较逻辑无法复用 | 新模块容易只验证调用次数 | 新增结果快照型 `AssertIdempotent` |
| HTTP 出站 mock server 无公共生命周期 helper | 后续 Integration 容易依赖真实外部服务 | 新增 `NewHTTPServer` |
| Permission 允许/拒绝断言重复 | 容易只覆盖成功路径 | 新增 `AssertPermissions` |
| SQLite 被当作 PostgreSQL 替代 | partial index、锁、JSONB 等语义可能漏测 | 明确禁止以 SQLite 声称覆盖 PostgreSQL 特性 |

## 5. 测试目录规范

1. 被测 package 的测试继续放在同目录 `*_test.go`。
2. 需要访问未导出实现时使用同 package 测试。
3. 验证公开契约或依赖边界时优先使用 `<package>_test`。
4. 跨 package 公共 helper 统一放在 `backend/internal/test`，导入别名使用 `testutil`。
5. fixture factory 默认留在拥有该模型的测试文件，不把业务 fixture 堆进公共包。
6. 大型协议样例或静态文件确有必要时使用所属 package 的 `testdata/`。
7. 禁止建立第二个公共 test helper 目录或引入大型测试 DSL。

`backend/internal/test` 使用普通 `.go` 文件，是因为需要被多个测试 package 导入；没有生产代码导入该 package，因此不会进入生产运行链路。

## 6. 测试命名规范

1. 顶层测试使用 `Test<Subject><Behavior>`，例如 `TestRunInTransactionRollsBackAndPropagatesError`。
2. 表驱动子用例名称描述业务场景，不使用无意义序号。
3. helper 必须调用 `t.Helper()`。
4. fixture 类型使用 `<subject>Fixture`。
5. 手写替身按语义命名为 `fake`、`spy`、`stub`、`capture` 或 `memory`。
6. 测试名称表达行为和期望，不绑定内部实现步骤。
7. 不使用 `time.Sleep` 等待异步结果；使用 channel、状态轮询上限或可控时钟。
8. 修改环境变量必须使用 `t.Setenv`，不得污染其他测试。

## 7. 分层测试规范

### 7.1 Unit Test

- 覆盖纯函数、状态转换、校验、错误包装和边界值。
- 优先表驱动测试。
- 不访问真实数据库、网络、Redis 或第三方系统。
- 一个失败应能定位到单一行为。

### 7.2 Repository Test

- 必须覆盖复杂查询、分页、唯一定位、原子状态更新和错误传播。
- 数据库无关 SQL 可使用 `testutil.OpenSQLite`。
- PostgreSQL partial unique index、exclusion constraint、JSONB、锁和方言 SQL 必须在真实 PostgreSQL 集成环境验证。
- Repository 测试不得通过 mock Service 反向构造。

### 7.3 Service Test

- 使用手写 fake/spy 隔离 Repository，或使用隔离数据库验证跨表事务。
- 必须覆盖事务、幂等、状态机、字段保护、错误传播和失败回滚。
- 测试生产事务 helper 时不得用 `WithRollback` 包住被测事务并据此宣称 commit 正确。
- 不通过 Controller 间接验证核心业务规则。

### 7.4 Permission Test

- 必须同时包含未授权失败和已授权成功。
- policy 测试使用项目真实 Casbin model。
- 接口权限还必须经过实际 middleware 路由验证。
- 前端按钮隐藏不能替代后端权限测试。
- 公共 `AssertPermissions` 只减少允许/拒绝断言重复，不替代授权关系和路由测试。

### 7.5 Seed Test

- 必须真实执行 Seed 两次并比较数据库结果。
- 快照至少包含记录数量和稳定业务键，并按稳定顺序返回。
- 必须检查重复组合键。
- Seed 拥有字段与用户维护字段分别验证。
- 禁止用“函数被调用两次”代替幂等结果验证。

### 7.6 Integration Test

- Gin/API 使用 `httptest` 构造真实 HTTP 边界。
- 外部 HTTP 使用 `testutil.NewHTTPServer`，不得依赖真实第三方环境。
- 跨层测试覆盖 DTO、middleware、Controller、Service 和响应契约中的关键路径。
- 真实数据库、Redis 或其他基础设施测试必须显式声明环境前置条件，不能静默连接开发环境。

## 8. Fixture 规范

1. 使用类型化 fixture 或局部 factory，显式提供稳定业务键。
2. 只填写当前测试需要的字段，避免复制完整生产对象。
3. 固定 ID 仅在当前隔离数据库内使用，不依赖生产自增序列。
4. fixture 之间的关系必须在测试中明确。
5. 使用 `testutil.MustCreate` 写入 fixture 并立即失败。
6. 查询结果比较前按稳定键排序。
7. 不共享可变全局 fixture。
8. JSON 文件仅用于协议样例或大结构，不用于隐藏普通表数据准备逻辑。

## 9. 数据库与回滚规范

### 9.1 OpenSQLite

统一 helper：

- 每次调用使用唯一命名内存数据库。
- GORM 使用 `SingularTable=true`。
- 使用平台 `model.Now`。
- 关闭迁移外键创建，与现有生产 GORM 基础配置一致。
- 日志静默。
- 单连接保证内存数据库一致性。
- 测试结束自动关闭连接。
- 可选传入模型并执行 AutoMigrate。

### 9.2 WithRollback

- 用于同一测试中的 fixture 数据隔离。
- callback 正常、失败退出或 panic 时均尝试 rollback。
- 不用于替代生产事务 commit/rollback 测试。
- 被测代码需要独立 transaction 时，应使用独立数据库并直接断言最终结果。

### 9.3 PostgreSQL 边界

SQLite 不覆盖：

- partial unique index；
- exclusion constraint；
- JSONB/operator；
- PostgreSQL 锁与并发抢占；
- 方言 SQL；
- 时间和类型转换差异。

上述能力进入 P2A/P2B 时必须补真实 PostgreSQL 集成测试方案。当前仓库尚未发现 testcontainers 或统一 PostgreSQL test harness，本任务不引入大型基础设施。

4. 历史测试数据库初始化仍有重复，按触达原则逐步迁移，不做批量重构。
5. 当前测试未启用 `t.Parallel()`；在全局 Gin mode、环境变量和共享 cache 完成隔离前不应批量开启。
6. 部分历史 Service 测试文件较大，应按领域后续拆分，不在本任务改造。
7. 外部 HTTP 客户端尚缺系统性的 timeout/retry mock 用例，将在 P2A Integration Runtime 开发时补齐。
8. 前端测试基线仍较弱；本 Task 按范围只处理 backend。
