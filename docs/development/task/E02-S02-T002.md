## 4. 领域对象边界

1. `org_structure` 表示管理架构定义，不表示组织单元。
2. `org_structure_node` 表示某个架构中的节点及父子关系。
3. `org_unit` 表示部门、事业部、区域、中心、团队等管理组织实体。
4. 管理树只使用 `org_structure_node.parent_node_id`，没有使用或新增 `org_unit.parent_id`。
5. 树节点定位使用 `structure_node_id`；业务引用和 options 持久化值使用 `org_unit_id`。
6. 同一 `org_unit` 出现于多个节点时保留每一个节点，不按 `org_unit_id` 去重。
7. 没有引入 `organization_id`、closure table、nested set、图数据库或新模型。
8. Response DTO 不返回 `source_id`、`source_version`、`path`、`sync_status` 或同步错误内部字段。

## 5. 管理架构查询

### 5.1 分页列表

`QueryStructures`：

- 复用 `request.Basic`、`sys_table/sys_table_field`、AdvancedQuery 表达式和平台分页语义。
- 支持分页、排序、QuickQuery、expressions、filters、`structure_type`、状态、默认架构、有效范围和 `as_of_date`。
- `org_structure` 没有法人字段；按 `legal_entity_id` 筛选时，通过有效 `org_structure_node` 与 `org_unit.primary_legal_entity_id` 的 `EXISTS` 关系过滤，不伪造架构字段。
- 返回白名单列表 DTO 和稳定 `total`。

### 5.2 详情

`GetStructureDetail`：

- 只接受内部 `structure_id`。
- 不存在返回稳定 `ErrOrgStructureNotFound`。
- 存在但不在请求可见范围内返回稳定 `ErrOrgStructureInactive`。
- 不直接返回 Model。

### 5.3 Options

`QueryStructureOptions`：

- 支持关键字、法人筛选、分页和已选 ID 回显。
- `value` 只能是内部 `structure_id`。
- `label` 使用“编码 - 名称”。
- 停用或历史已选对象可回显，并标记 `disabled=true`。

## 6. 组织单元查询

### 6.1 分页列表

`QueryOrgUnits`：

- 支持分页、排序、QuickQuery、expressions、filters、法人、类型、状态、有效范围和 `as_of_date`。
- QuickQuery 使用元数据已开放的 `code/name`。现有 `org_unit` 模型没有 `short_name`，本 Task 未擅自新增字段。
- 对外正式法人参数为 `legal_entity_id`；T003 已存在的 `primary_legal_entity_id` 保持兼容，两者同时传入不同值时返回参数错误。
- 默认不返回停用、源删除、过期或平台软删除对象。

### 6.2 详情

`GetOrgUnitDetail`：

- 只接受内部 `org_unit_id`。
- 使用白名单 DTO。
- 可返回安全的所属法人 `id/code/name` 摘要。
- 法人摘要不可用时保留 `primary_legal_entity_id`，不伪造显示数据。

### 6.3 Options

`QueryOrgUnitOptions`：

- `value` 只能是内部 `org_unit_id`。
- 支持关键字、法人、架构、分页和已选 ID 回显。
- 传入 `structure_id` 时，严格通过 `org_structure_node` 的有效引用过滤，不使用 `org_unit.parent_id`。
- 先验证架构存在且在请求范围内。
- 历史或停用已选对象可回显，但默认不能作为新选择项。

## 7. 管理组织树算法

`GetStructureOrgTree` 的固定读取链路：

1. 查询并验证一个 `org_structure`。
2. 一次查询该架构的节点，最多读取 `5001` 条用于上限检测。
3. 对节点中的组织 ID 去重后，一次批量查询相关 `org_unit`。
4. 使用 `map[structure_node_id]node` 和 `map[org_unit_id]unit` 在内存组装树。

树规则：

- 正常请求固定三次数据库读取，不随节点数量增加，不存在 N+1。
- 单次最多返回 `5000` 个可见节点，超限返回稳定业务错误。
- 支持多根和 `root_node_id` 子树。
- `root_org_unit_id` 仅作为便利定位；零匹配返回节点不存在，一个匹配返回对应子树，多个匹配返回明确歧义错误。
- `root_node_id` 与 `root_org_unit_id` 不能同时传入。
- 自循环和多节点循环均在递归前检测，返回稳定业务错误。
- 缺失可见父节点的孤儿节点提升为根，标记 `orphan=true` 并记录内部 ID 诊断日志，不挂载到错误父节点。
- 相同 `org_unit_id` 的多个 `structure_node_id` 均保留。
- 关键字匹配组织编码或名称，结果包含命中节点及其必要祖先路径。
- 兄弟节点按节点 `sort`、组织编码、节点 ID 稳定排序。
- DTO 同时返回 `structure_node_id` 和 `org_unit_id`，不提供含混的统一 `value`。

## 8. 有效性规则

默认 `only_effective=true`。

管理架构当前有效：

1. `status = enabled`。
2. `valid_from` 为空或不晚于 `as_of_date`。
3. `valid_to` 为空或不早于 `as_of_date`。
4. 平台软删除记录不可见。

组织单元和架构节点当前有效：

1. `status = enabled`。
2. `source_deleted = false`。
3. 有效期覆盖 `as_of_date`。
4. 平台软删除记录不可见。

现有 `org_structure` 已评审模型没有 `source_deleted` 字段，本 Task 未修改模型；其有效性按现有状态、有效期和平台软删除判断。

其他规则：

- `include_disabled=true` 显式放开状态过滤。
- `include_history=true` 显式放开源删除和有效期过滤，但不会自动放开停用状态。
- `only_effective=false` 同时放开停用和历史镜像。
- 有效期边界为包含关系，按平台 `Asia/Shanghai` 时区解析 `YYYY-MM-DD`。
- 同步失败状态不改变当前有效镜像。

## 10. Service、Repository、Controller 边界

- Controller 只做参数绑定、Validation、元数据读取、Service 调用和统一 Response。
- Service 负责有效性、关联语义、树构建、循环检测、歧义判断和业务错误。
- Repository 负责固定关系谓词、分页、批量读取和安全列选择，不包含权限或树业务规则。
- 关系型分页继续使用 `request.Basic` 与平台 `ExecuteQuery` 语义；固定 `EXISTS` 关系由 Organization Repository 添加。
- 只读查询不创建无意义事务。
- 其他模块必须调用 Organization Service，不得直连 Organization Repository。
- 所有错误使用冻结的 AdminError/myerrors 体系，不依赖错误字符串。
