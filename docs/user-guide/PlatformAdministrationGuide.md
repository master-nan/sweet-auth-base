# Sweet Platform 平台管理员使用手册

## 1. 适用对象

本手册面向平台管理员、实施人员、业务管理员和项目负责人，用于回答四个问题：

1. 平台现在有哪些功能。
2. 每项功能解决什么问题。
3. 功能之间按什么顺序配置。
4. 出现异常时先到哪里检查。

本手册依据当前菜单、页面、权限按钮和服务端接口编写。页面上没有的能力，不会因为底层已有接口或历史设计提到过就被写成可操作功能。

## 2. 平台功能地图

| 模块 | 解决的问题 | 主要使用者 | 当前主要入口 |
| --- | --- | --- | --- |
| 系统管理 | 账号、角色、菜单、按钮权限、应用、短信和审计 | 平台管理员 | 系统管理 |
| Organization | 统一查看法人、组织、岗位、员工、任职和业务同步结果 | 业务管理员、实施人员 | 组织管理 |
| Data Permission | 控制用户在“有权进入功能”后还能看到哪些业务数据 | 平台管理员、实施人员 | 系统管理 > 数据权限 |
| Metadata / SysTable | 管理业务表和字段的显示、查询及运行时元数据 | 实施人员、开发人员 | 开发管理 > 数据管理 |
| File | 为业务页面提供上传、分片、秒传、预览、下载和删除 | 业务用户、实施人员 | 嵌入具体业务页面，无独立文件中心 |
| Integration | 配置外部系统、接口、凭证、重试和同步运行 | 集成管理员、实施人员 | 集成中心 |

管理员通常先完成账号和功能权限，再按业务需要配置 Organization、Data Permission、Metadata 和 Integration。File 是被业务页面调用的公共能力，不需要单独建立文件目录或文件角色。

## 3. 权限与管理员分工

### 3.1 四类常见使用者

- **平台管理员**：维护用户、角色、菜单、按钮权限和平台级配置。
- **业务管理员**：查看组织主数据、业务同步结果和本业务范围内的数据。
- **实施人员**：配置元数据、数据权限、外部接口和同步任务。
- **开发人员**：在已有平台能力上接入业务模块。开发扩展不属于本手册范围。

角色名称不是权限判断依据。系统根据角色实际分配的菜单和按钮决定功能权限，因此不要把“管理员”“实施人员”等称呼当成硬编码角色。

### 3.2 用户、角色、菜单和按钮

- **用户**是可以登录平台的账号。
- **角色**是一组功能权限的集合。
- **菜单**决定用户能否进入某个页面。
- **按钮权限**决定用户能否在页面中查询、查看详情、创建、编辑、启停或执行其他操作。

平台使用 Casbin 校验这些功能权限。对管理员而言，可以把它理解为：角色里分配的菜单和按钮不仅影响页面是否显示，也约束对应服务端接口。仅隐藏按钮不等于授权，直接访问地址也不能绕过权限检查。

### 3.3 推荐授权流程

1. 在“系统管理 > 菜单管理”确认菜单和所需按钮已经存在。
2. 在“系统管理 > 角色管理”创建或选择角色。
3. 给角色分配菜单和按钮。
4. 在“系统管理 > 用户管理”创建用户或选择已有用户。
5. 给用户分配至少一个角色。
6. 让用户重新登录，验证菜单、按钮和接口访问。

用户管理还提供重置密码和解除登录锁定。重置密码后，现有令牌会失效，用户需要使用临时密码重新登录并修改密码。

遇到“页面能进但没有按钮”时，先检查角色的按钮权限；遇到“页面或接口无权访问”时，同时检查菜单权限、按钮权限和数据权限。

### 3.4 其他管理员页面

- **应用管理**：维护开放 API 调用方的 App Key/Secret。Secret 只在创建或轮换成功后展示一次，应用身份不能替代用户登录身份。
- **短信管理**：维护短信模板，不负责直接授予用户登录权限。
- **配置管理**：维护登录安全、密码策略、系统品牌和邮件配置，并可发送测试邮件。该页面实际位于“开发管理”。
- **字典管理**：维护平台页面使用的受控字典及字典项，实际位于“开发管理”。
- **审计日志**：按条件查看访问和管理操作详情；该页面只读，不能修改历史审计事实。

应用 Secret、密码、短信验证码和 Token 都不应写入工单、截图或普通日志。

## 4. Organization 使用说明

Organization 是平台的组织主数据镜像，不是本地 HR 系统。当前管理页面以查询、核对和账号绑定为主，没有手工创建或编辑法人、组织、岗位、员工和任职的入口。

更完整的页面说明见[组织管理使用说明](OrganizationManagementUserGuide.md)。

### 4.1 七类组织对象

| 对象 | 含义 | 典型用途 |
| --- | --- | --- |
| 法人 | 法律责任、合同、开票和核算主体 | 合同主体、开票主体 |
| 组织单元 | 稳定的业务组织主体 | 业务单据的组织归属 |
| 组织结构 | 一套组织关系视图 | 管理树、法人树 |
| 结构节点 | 某个组织单元在某棵结构树中的位置 | 展示父子关系 |
| 岗位 | 企业中的工作位置 | 人员工作岗位 |
| 员工 | 企业人员的业务身份 | 业务经办人、负责人 |
| 任职 | 员工与法人、组织、岗位在一段时间内的关系 | 当前、历史和未来任职 |

### 4.2 组织单元与结构节点为什么不同

假设“华东销售部”是一个稳定部门：

- 在日常管理结构中，它可能位于“销售事业部”下面。
- 在法人结构中，它可能位于某个法人公司下面。
- 将来组织树调整时，它在树中的父节点可能变化，但部门本身仍是同一个组织单元。

因此，业务表保存组织归属时应引用 **组织单元（`org_unit`）**，不要保存结构节点。结构节点只用于表达某个组织单元在一棵树中的位置。

### 4.3 实际查看顺序

当前 Organization 数据来自受控同步或已有初始化数据，管理员按以下顺序核对：

1. 在“组织管理 > 组织架构”切换管理架构和法人架构，核对法人、组织单元和父子关系。
2. 在“组织管理 > 岗位”核对岗位所属组织、状态和有效期。
3. 在“组织管理 > 人员与任职”核对员工状态、账号绑定和已有任职。
4. 在“组织管理 > 同步批次”查看一次业务消费的数量和状态。
5. 在“组织管理 > 同步异常”查看具体对象、动作和稳定原因码。

页面中的“刷新”只重新读取平台内已有数据，不会直接调用外部 HR 接口。要发起同步，应到“集成中心 > 同步任务”操作，并且相关 Runner、Worker 和 Consumer 必须已由实施人员正确启用。

### 4.4 Employee 不等于 User

- **Employee** 是员工在企业组织中的业务身份。
- **User** 是登录 Sweet Platform 的平台账号。

员工不一定需要登录账号，例如仅用于审批链、业务归属或历史记录时，可以只有 Employee。需要登录平台时，管理员应先创建 User，再到员工详情中显式绑定已有账号。

绑定不会：

- 自动创建账号。
- 自动分配角色。
- 按姓名、手机号、邮箱或员工编号猜测账号。
- 在解绑时删除账号或员工。

### 4.5 HR 同步当前状态

平台已具备法人、双组织结构、岗位、员工和离职安全处理的适配能力，但当前真实 HR 源的生产启用条件尚未满足，七类 Organization HR Consumer 均保持停用。因此：

- 当前不能把真实 HR SyncTask 当作已开放的生产功能。
- 页面中可能没有可选择的 HR Consumer，这是受控状态，不是数据加载故障。
- 当前不支持通过生产 HR Consumer 创建主任职或兼职任职。
- 当前离职能力只处理已确认的安全子集，不会自动处理再入职或账号停用。

## 5. Data Permission 使用说明

功能权限回答“能不能进入页面、点击按钮”；数据权限回答“进入后能看到哪些记录”。两者相互独立，通常必须同时满足。

更完整的配置说明见[数据权限管理员手册](DataPermissionUserGuide.md)。

### 5.1 从“只能看本部门数据”理解配置对象

以“销售人员只能查看本部门订单”为例：

- **Resource（资源）**：订单。
- **Operation（操作）**：查询订单、查看订单详情。
- **Ownership Field（归属字段）**：订单记录中的所属组织字段。
- **Dimension（维度）**：管理组织。
- **Policy（策略）**：只允许当前用户有效任职所在组织。
- **Rule（规则）**：将“所属组织字段”与“当前用户组织范围”进行匹配。
- **Grant（授权）**：把这项策略授予销售角色，并限定到订单查询和详情操作。

### 5.2 推荐配置顺序

1. 在“数据资源”中选择或创建资源。
2. 为资源配置受保护的操作，如查询、详情、更新或导出。
3. 配置 Ownership Field，说明哪一个字段代表员工、管理组织或法人归属。
4. 选择系统已有维度。当前内置维度包括法人、管理组织和员工，维度本身为只读目录。
5. 创建 Policy，并在策略中配置 Rule。
6. 创建 Grant，选择用户或角色、资源、操作和 Policy。
7. 分别执行资源、策略和授权的“配置检查”。
8. 检查通过后启用配置，再用目标账号验证。

Ownership Field 必须来自 Metadata Runtime 或服务端注册字段，不能输入任意数据库字段或 SQL 表达式。

当前“归属定义”页面可以创建和启停配置，但已有配置没有独立编辑表单。发现字段、维度或绑定方式配置错误时，不要把启停按钮当成编辑；应先停用错误配置，再按项目变更流程建立正确配置。

### 5.3 三个常见例子

#### 例一：只能看本人数据

将资源的“负责人/员工”归属字段关联到员工维度，策略范围取当前登录账号已绑定的 Employee，再把策略授予对应角色。未绑定 Employee 的账号不会凭用户名或手机号自动获得人员范围。

#### 例二：只能看本部门数据

将资源的组织归属字段关联到管理组织维度，策略范围取当前账号有效任职对应的组织。若业务要求包含下级部门，应明确选择“本级及下级”的关系规则，不要把“本部门”和“本部门及全部下级”当成同一种范围。

#### 例三：某角色可以看多个组织范围

为角色创建一项 Grant，策略中配置允许的多个管理组织范围，或使用账号有效任职计算出的组织集合。多个范围应通过正式规则表达，不要给用户额外菜单权限来替代数据范围。

### 5.4 配置检查失败时

重点检查：

- 资源和操作是否启用。
- Ownership Field 是否存在且可用于过滤。
- 字段对应的维度是否正确。
- Policy 和 Rule 是否启用、有效期是否正确。
- Grant 的用户或角色是否存在。
- 目标账号是否有有效 Employee 绑定或组织任职。

## 6. Metadata / SysTable 使用说明

“开发管理 > 数据管理”用于维护平台对业务表和字段的认识。它既服务低代码页面，也向 Data Permission 和未来运行时功能提供字段事实。

### 6.1 可配置内容

- 表编码、表名称和当前表类型。
- 字段编码、显示名称、存储类型和逻辑类型。
- 输入组件类型、字典和字段联动。
- 是否在列表、新增、编辑和详情中显示。
- 快捷查询、高级查询和排序能力。
- 表单、详情布局宽度和显示顺序。
- 已有索引和字段关系元数据。
- 从已有数据库表初始化，以及同步字段和索引。
- 发布或取消发布对应的低代码菜单。

字段类型的详细说明见[字段类型指南](FieldTypeGuide.md)，字段联动见[字段联动配置](LinkageConfig.md)，低代码页面配置见[低代码配置手册](LowCodeManual.md)。

### 6.2 三种字段类型不要混淆

- **存储类型**描述数据库如何保存数据，例如整数、字符串或时间。
- **逻辑类型**描述运行时如何理解数据，例如金额、布尔值或日期时间。
- **UI 组件类型**描述页面使用输入框、下拉框、日期组件等哪种控件。

管理员不应仅因为页面想用下拉框，就改变数据库存储类型；也不应把数据库的 `varchar` 直接当作所有业务字段的完整含义。

### 6.3 Runtime Metadata

Runtime Metadata 是系统运行时使用的安全字段视图，不是一个单独管理页面。Data Permission 等模块通过它读取字段编码、显示名称、逻辑类型、查询能力和列表显示等稳定信息，而不是直接读取数据管理页面的全部配置。

跨模块引用字段时，使用稳定的表编码和字段编码。显示名称只用于给用户阅读，不能作为字段身份。

### 6.4 受保护字段

密码、Token、Secret、Credential 和审计控制字段等受保护字段，不能被配置为普通列表字段、快捷查询、高级查询或数据权限过滤字段。这是服务端规则，不是只在页面上隐藏。

字段名和表名必须是合法标识符，不能填写 SQL、脚本或表达式来绕过字段白名单。

### 6.5 当前范围

数据管理提供快捷查询、高级查询、动态列和Query Scheme校验所需的元数据。只有注册Query Scope且适合标准列表的页面接入查询方案；Dictionary、Tree、Diagnostic和Report等特殊页面按各自布局复用适合的能力。

## 7. File 使用说明

File 没有独立的“文件管理”菜单。上传、预览和下载由具体业务页面或低代码页面调用；服务端虽有受控删除能力，但当前没有通用删除入口。

### 7.1 当前能力

- 小文件普通上传。
- 大文件分片初始化、分片上传、进度查询和合并；当前前端默认超过 5 MiB 使用分片。
- 同一所有者已有相同文件且存储完整时的秒传。
- 文件元数据查询。
- 受权限保护的预览和下载。
- 服务端受控删除文件元数据和对应存储对象。

秒传不会因为客户端提交相同摘要就允许引用别人的文件。平台仍会检查文件所有者、业务权限和存储完整性。

当前没有独立文件列表或生命周期页面，现有业务表单也没有通用“物理删除文件”按钮。表单中移除附件通常只是解除当前业务记录的引用，不等于删除服务器文件；需要删除能力时，应由具体业务页面显式接入受控删除操作。

### 7.2 预览和下载

预览地址与下载地址用途隔离：

- 预览地址只能用于预览。
- 下载地址只能用于下载。
- 地址过期、被篡改、缺少用途或用途不匹配时都会被拒绝。

管理员不要把完整签名地址记录在工单、日志或长期文档中。需要访问时，应由业务页面按用途重新申请。

### 7.3 多实例部署限制

分片暂存当前保存在接收上传的应用节点本地，合并协调也在单进程内完成。多实例部署时，同一个上传会话的分片和合并请求需要落到同一节点，通常通过会话粘性实现。当前尚未提供共享分片暂存。

## 8. Integration 使用说明

Integration 用于受控调用外部系统。以“从外部 HR 系统同步组织数据”为例，完整配置关系如下：

```text
外部系统
  -> 集成凭证
  -> 重试策略（可选）
  -> 接口定义（固定版本）
  -> 同步任务（固定接口与 Consumer 版本）
  -> 同步批次
      -> Execution（一个具体时间片）
          -> Attempt / 调用日志（一次真实 HTTP 尝试）
          -> Consumer 业务处理结果
  -> Checkpoint 推进
```

### 8.1 推荐配置顺序

1. 创建并启用“外部系统”。
2. 创建“集成凭证”，填写秘密并启用。
3. 按需创建并启用“重试策略”。
4. 创建“接口定义”草稿，引用凭证和重试策略，核对后启用。
5. 创建“同步任务”草稿，固定接口版本和 Consumer 版本，配置调度、窗口和输入后启用。
6. 由运维在服务端配置中启用 Sync Runner 和 Integration Worker。
7. 等待 Cron，或在启用任务上点击“运行一次”。
8. 在“同步批次”查看整次同步，在“执行记录”查看时间片，在“调用日志”查看每一次实际尝试。

### 8.2 外部系统

外部系统代表一个独立外部平台，例如 HR、ERP、TMS 或 WMS。`system_code` 是长期稳定标识，创建后不能修改；名称和负责人用于管理和排查。

Base URL 只配置系统根地址，接口的相对路径放在接口定义中。当前执行端使用 HTTPS-only 网络策略，并拒绝未批准的私网、回环和云元数据地址。页面虽然可以选择 HTTP 协议，但当前 Worker 不会执行不符合安全策略的地址，生产配置应使用经过批准的 HTTPS 地址。

### 8.3 接口定义

接口定义描述一次技术调用的固定契约，包括：

- 所属外部系统。
- 接口编码和版本。
- HTTP Method 与相对路径。
- 凭证和重试策略引用。
- 超时时间。
- 响应大小限制，最大不能超过平台 64 MiB 上限。
- 输入契约和安全的请求参数规则。

只有草稿可以直接编辑。已经启用的接口如需修改，应创建新版本；旧版本仍可能被已有 SyncTask 或历史 Execution 引用，原地修改会让历史运行失去可解释性。

当前页面尚不能编辑完整输入契约和远端幂等配置，需要实施人员先确认当前接口是否能仅通过页面字段安全表达。

### 8.4 集成凭证

凭证当前可配置 Basic、API Key、Bearer Token 和 OAuth Client 类型；但当前运行时真正可执行的是 Basic、API Key 和 Bearer Token，OAuth Client 尚未实现执行支持。

秘密采用“只写不可读”：

- 创建或轮换时可以提交秘密。
- 保存后详情只显示安全指纹、版本和有效期。
- 管理员之后看不到原始秘密是正常行为。

**轮换**会生成新版本，用于替换仍需继续使用的秘密；**吊销**表示该凭证永久不可再用，不能恢复。临时暂停使用应选择停用，而不是吊销。

### 8.5 重试策略

重试策略可配置：

- 最大尝试次数。
- 初始和最大等待时间。
- 固定或指数退避。
- 是否加入随机抖动，避免大量请求同时重试。
- 整体重试窗口。
- 可重试错误分类和 429、502、503、504 等受控状态码。
- 是否尊重服务端 `Retry-After`。

重试只处理网络、超时和受控远端技术失败。HTTP 已成功但 Consumer 业务处理失败时，不会自动重试；这类问题应先修复数据或业务规则，再由下一次同步的 Lookback 重放收敛。

### 8.6 SyncTask

SyncTask 把接口版本、Consumer 版本、调度和时间窗口组合成一个可运行同步任务。

主要配置包括：

- 稳定任务编码和版本。
- 手工调度或五段 Cron。
- IANA 时区。
- `none` 或 `timestamp` Checkpoint。
- 初始 Checkpoint。
- Lookback。
- 顺序时间切片。
- 受控静态输入和窗口绑定。

只有草稿可以直接编辑。已启用任务需要通过“创建版本”修改。同一任务编码只允许一个启用版本。

#### Checkpoint 示例

假设当前 Checkpoint 是 `10:00`，本次逻辑窗口结束于 `11:00`：

```text
逻辑窗口：[10:00, 11:00)
```

如果任务按 30 分钟切片，平台依次处理：

```text
Slice 1：[10:00, 10:30)
Slice 2：[10:30, 11:00)
```

只有 Slice 1 技术调用和 Consumer 业务处理都成功，Checkpoint 才推进到 `10:30` 并创建 Slice 2。Slice 2 成功后才推进到 `11:00`。中间失败、等待重试或业务失败都不会越过该时间片。

创建 Task 新版本时，平台继承最新有效 Checkpoint，避免从头重复同步。Lookback 只把请求开始时间向前移动一小段，用稳定业务主键消化边界重复；它不会把逻辑 Checkpoint 倒退。

#### lower_bound_only

有些外部接口只支持“更新时间大于等于某个时间”，没有请求结束时间。`lower_bound_only` 可以让平台仍然冻结逻辑结束时间，并要求 Consumer 只处理逻辑窗口内的数据。

这种模式不能限制外部系统实际返回到多晚，也不能保证响应大小有上界。管理员必须通过较小窗口、受控公司分区和实际响应量验证控制风险；响应超过接口或 Consumer 限制时，任务会失败，平台不会自动放宽 64 MiB 上限。

### 8.7 SyncBatch、Execution 和调用日志

- **SyncBatch**：一次 SyncTask 运行，状态为待运行、运行中、成功或失败。
- **Execution**：批次中的一个具体接口调用，通常对应一个顺序时间片。
- **Attempt / 调用日志**：同一个 Execution 的一次真实 HTTP 尝试。发生技术重试时，仍是同一个 Execution，只增加 Attempt。

```text
Batch
  |-- Execution Slice 1
  |     |-- Attempt 1：HTTP 503
  |     `-- Attempt 2：HTTP 200 + Consumer 成功
  `-- Execution Slice 2
        `-- Attempt 1：HTTP 200 + Consumer 成功
```

SyncBatch 页面用于判断整次运行和 Checkpoint；Execution 页面用于判断当前时间片、重试和 Consumer 结果；调用日志用于判断某次 HTTP 尝试的状态、耗时和错误分类。页面不会展示完整请求快照、响应 Body、Authorization、Cookie 或凭证秘密。

执行记录允许取消“待执行”或“等待重试”的 Execution；运行中或已经结束的 Execution 不能取消。取消单个同步 Execution 会使对应 Batch 最终失败，平台不提供 Batch 取消或批量取消。

### 8.8 Worker 和 Sync Runner

- **Integration Worker**领取 Execution、读取受控凭证并执行 HTTP。执行记录页面可以查看 Worker 是否启用、是否运行、Worker ID、活动任务和最近轮询。
- **Sync Runner**发现到期任务、创建 Batch、协调切片和推进 Checkpoint。当前没有 Runner 状态页面。

两者默认关闭，不能通过管理页面启动。生产启用由运维修改服务端配置并重启实例；每个运行实例应使用稳定且唯一的 `worker_id` 或 `runner_id`。

“运行一次”只创建手工 Batch，后续切片和 Execution 仍需要 Sync Runner；Execution 的实际 HTTP 调用仍需要 Worker。

### 8.9 常见 Integration 问题

| 现象 | 常见原因 | 去哪里看 |
| --- | --- | --- |
| 接口显示“当前不可用” | 外部系统、凭证或重试策略未启用，或引用版本失效 | 外部系统、集成凭证、重试策略、接口详情 |
| Credential 错误 | 凭证停用、吊销、过期或秘密无效 | 凭证详情、Execution、调用日志 |
| Batch 长时间停在待运行 | Sync Runner 未启用，或任务尚未被协调 | 服务端 Runner 配置、同步批次 |
| Execution 长时间停在待执行 | Worker 未启用或未轮询 | 执行记录顶部 Worker 状态 |
| HTTP 超时 | 接口超时配置过短、网络异常或远端处理过慢 | Execution 和调用日志 |
| 429/503 后等待 | 命中受控重试策略 | Execution 的下次重试时间、调用日志的 Retry-After 和延迟 |
| HTTP 200 但 Execution 失败 | Consumer 返回业务失败、超时或 panic | Execution 的同步业务结果、Organization 同步异常 |
| Checkpoint 不推进 | 当前 Slice 失败、等待重试或 Consumer 失败 | SyncBatch -> Execution -> 调用日志 |
| 响应过大 | 接口实际响应超过 Interface 或 Consumer 限制 | 调用日志的响应大小和错误分类；缩小窗口或使用受控分区 |
| 地址被拒绝 | 使用 HTTP、回环/私网/云元数据地址，或域名解析不满足安全策略 | 外部系统、接口定义、Execution 错误分类 |

业务失败不会进入技术重试；Sync 也不会自己执行 HTTP 或修改 Retry 的下一次运行时间。

## 9. 查询方案与Report管理

### 9.1 查询方案

查询方案管理通过支持该能力的业务列表进入，不建立独立一级菜单。普通用户维护自己的PERSONAL方案；拥有`query_scheme_shared_manage` Capability的管理员可以维护PUBLIC、ROLE和PAGE_DEFAULT方案。

- PUBLIC对拥有目标页面访问权限的用户可用。
- ROLE只对匹配角色用户可见，可关联最多32个有效角色。
- PAGE_DEFAULT每个Scope最多一个启用默认。
- 共享方案不能读取或修改其他用户的PERSONAL方案。
- Scheme条件与Data Permission按AND组合，不能扩大数据范围。
- Shared启停是独立管理动作，不与内容保存合并成半成功流程。

### 9.2 Report

报表管理根据菜单和按钮权限提供创建、设计、运行、发布版本、发布菜单、版本查看、CSV导出、停用和删除。设计中的草稿与已发布快照分离：编辑草稿不会改变当前线上运行结果，只有发布新版本后正式运行和导出才读取新快照。

table数据集复用Metadata和Data Permission。SQL数据集必须通过只读安全检查、执行Deadline和结果限制，但不会自动注入任意业务表的数据权限；只有受控管理员才能配置。不要把SQL数据集当作绕过业务Service的通用查询接口。

## 10. 三个典型管理员工作流

### 10.1 新员工需要平台账号和权限

1. 确认员工已经存在于“组织管理 > 人员与任职”。
2. 在“系统管理 > 角色管理”选择合适角色，核对菜单和按钮。
3. 在“系统管理 > 用户管理”创建登录账号并分配角色。
4. 回到员工详情，将该 Employee 与已有 User 显式绑定。
5. 让用户重新登录，验证功能权限。
6. 如果业务页面还有数据权限，再验证其 Employee、组织任职和对应 Grant。

不要先绑定姓名相近的账号，也不要期待员工同步自动创建 User 或角色。

### 10.2 新业务表接入 Data Permission

1. 在“开发管理 > 数据管理”初始化或创建表元数据。
2. 同步并核对字段，确保业务归属字段存在且不是受保护字段。
3. 配置字段显示和查询能力。
4. 在“系统管理 > 数据权限”创建资源和操作。
5. 将业务归属字段配置为 Ownership Field，并选择正确维度。
6. 创建 Policy、Rule 和 Grant。
7. 完成三类配置检查并启用。
8. 用有范围、无范围和多范围账号分别验证。

### 10.3 新外部接口接入 Integration

1. 新建外部系统，使用稳定系统编码和经过批准的 HTTPS Base URL。
2. 新建凭证，确认秘密只写和轮换方案，随后启用。
3. 按需创建重试策略，明确哪些技术错误可重试。
4. 创建接口定义草稿，配置固定路径、Method、超时、响应上限、凭证和重试策略。
5. 核对输入契约是否能通过当前页面表达，再启用接口版本。
6. 如需同步，确认服务端已静态注册且启用对应 Consumer，再创建 SyncTask。
7. 配置 Cron、时区、Checkpoint、Lookback 和 Slice，启用任务。
8. 请运维启用 Sync Runner 和 Worker。
9. 先做一次小窗口验证，再查看 Batch、Execution、调用日志和业务同步结果。

## 11. 当前明确未支持或未开放

- Query Center不保存列显示、列宽、分页、跨表查询、SQL、收藏、分享流程、审批、订阅或查询历史版本。
- Report当前通过报表中心、报表管理、设计器和已发布报表运行页提供table/sql dataset、sheet/cell/binding、发布版本、运行、CSV导出和执行日志能力；不提供独立Workbench入口，也不提供外部数据源、复杂图表大屏、打印分页、填报、定时调度、邮件订阅或多数据集复杂联动。
- 当前真实 HR 生产 Consumer 均为停用状态，真实 HR 同步尚不满足生产启用条件。
- 当前不支持 HR 主任职同步、生产兼职同步、自动再入职和物理删除判断。
- File 分片暂存不支持多实例共享，需要会话粘性。
- Integration 不支持 Batch 取消、Batch 重跑、自定义同步窗口、补数、Dry Run、立即重试、Checkpoint 手工修改或 Payload 查看。
- Integration 当前不执行 OAuth Client 凭证，接口运行采用 HTTPS-only 策略。
- Sync Runner 没有管理页面状态和启停入口，Worker 也只能由服务端配置启停。

## 13. 排查顺序

遇到问题时，建议依次确认：

1. 当前账号是否有菜单和按钮功能权限。
2. 该页面是否还受 Data Permission 限制。
3. 对象本身是否启用、有效且引用版本正确。
4. Worker、Runner 或相关服务端功能是否已启用。
5. 技术失败看 Execution 和调用日志，业务失败看 Consumer 结果及业务同步异常。
6. 不要把页面没有展示的秘密、Payload 或内部错误当作缺失功能，这些信息按安全规则不会返回。
