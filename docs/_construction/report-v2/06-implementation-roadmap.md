# Report V2 落地路线

## 路线原则

Report V2 先解决产品信息架构和普通表格报表创建体验，再整合高级 Sheet 和数据集实体化。

原因：

1. 工作台和快速表格是用户最直接感知的问题。
2. V1 后端发布、运行、导出闭环已经可复用。
3. 高级 Sheet 有现成基础，不应先重写。
4. `report_dataset / report_datasource` 影响后端模型，应在产品流程稳定后再落地。

## V2-0：产品设计和技术设计文档

目标：

1. 明确边界。
2. 明确命名策略。
3. 明确信息架构。
4. 明确领域模型。
5. 明确 API 策略。
6. 明确 V1 兼容和迁移策略。

本阶段不做：

1. 不写 V2 页面代码。
2. 不改后端。
3. 不新增表。
4. 不替换 V1 菜单。

验收标准：

1. `docs/_construction/report-v2/` 下设计文档完成。
2. 产品、前端、后端、迁移策略达成一致。

## V2-1：新报表工作台 UI 空壳

目标：

1. 新建 `frontend/src/pages/report-v2/` 前端目录。
2. 新建 workbench 页面。
3. 做静态结构和基础交互。
4. 可以调用现有 `queryReports`。
5. 不替换 V1 路由。

本阶段不做：

1. 不删除 V1 页面。
2. 不改后端。
3. 不改菜单和权限。
4. 不实现完整设计器。

验收标准：

1. 工作台页面能展示列表。
2. 普通用户和管理员操作区域有清晰区分。
3. 不影响 V1 页面。

## V2-2：新建报表向导

目标：

1. 类型选择。
2. 基本信息。
3. 数据来源。
4. 字段与参数。
5. 预览保存。
6. 先只支持快速表格报表。

本阶段不做：

1. 不做高级 Sheet 整合。
2. 不做外部数据源。
3. 不做数据集实体化。

验收标准：

1. 用户能通过向导创建快速表格报表草稿。
2. 草稿写入现有 `report_definition`。
3. 生成现有 `query_config / layout_config`。

## V2-3：快速表格报表设计器

目标：

1. 字段勾选。
2. 列配置。
3. 查询参数配置。
4. 生成现有 `sheet/cell/binding`。
5. 保存草稿。

本阶段不做：

1. 不做图表。
2. 不做打印。
3. 不做填报。
4. 不做复杂 BI 建模。

验收标准：

1. 选择系统表后能生成表格报表。
2. 保存后重新打开能回显快速配置。
3. 不需要用户理解 cell / binding / formula。

## V2-4：接入 V1 后端发布/运行/导出闭环

目标：

1. 复用 `/design-preview`。
2. 复用 `/publish`。
3. 复用 `/run`。
4. 复用 `/export`。
5. 复用 `/versions`。

本阶段不做：

1. 不新增 `/report-v2` API。
2. 不改运行态只读发布版本规则。
3. 不改后端导出规则。

验收标准：

1. 保存草稿后能设计时预览。
2. 发布生成版本快照。
3. 工作台运行读取发布版本。
4. 导出走后端受控导出。
5. 版本列表可查看。

## V2-5：高级 Sheet 模式整合

目标：

1. 把当前 Sheet 设计器作为高级模式挂入。
2. 复用 `ReportSheetCanvas`。
3. 复用 `ReportInspectorPanel`。
4. 复用 `ReportResourcePanel`。
5. 旧 V1 报表默认进入高级 Sheet 模式。

本阶段不做：

1. 不重写 Sheet 画布。
2. 不重写预览组件。
3. 不强行把旧复杂 Sheet 转换成快速表格。

验收标准：

1. 旧报表可打开。
2. 高级模式能继续编辑复杂布局。
3. 快速表格可切换到高级模式继续精修。

## V2-6：数据集模型设计与落地评估

目标：

1. 评估 `report_dataset`。
2. 评估 `report_datasource`。
3. 评估 `report_permission`。
4. 明确是否需要独立数据集管理中心。

本阶段不做：

1. 不默认引入外部数据源。
2. 不过早拆分后端服务。
3. 不破坏现有内嵌 dataset 配置。

验收标准：

1. 明确哪些场景必须用可复用数据集。
2. 明确外部数据源安全方案。
3. 明确是否需要报表级权限模型。

## V2-7：V2 转正

目标：

1. 旧 `report` 改为 `report-legacy`。
2. 新 `report-v2` 改为 `report`。
3. 菜单切换到新版报表工作台。
4. 隐藏旧 V1 菜单。
5. 保留旧路由一段时间用于回退。

本阶段不做：

1. 不立即删除 V1 代码。
2. 不迁移到 `_v2` 表。
3. 不删除已发布版本。

验收标准：

1. 正式菜单展示“报表工作台”。
2. 用户不再看到“报表 V2”命名。
3. 旧入口可回退。
4. 新入口覆盖主要业务流程。

## 风险控制

1. V2 不直接删除 V1 页面。
2. V2 初期不改菜单和权限。
3. V2 初期不改后端运行态规则。
4. V2 初期不新增外部数据源。
5. V2 初期不做图表大屏。
6. V2 初期不做填报。
7. V2 初期不做打印分页。
8. V2 初期不做定时订阅。
9. V2 先做普通表格报表，再扩展高级能力。
10. 旧 V1 报表默认进入高级 Sheet 模式。
11. Dataset 是正式概念，但第一阶段可以先不落表。
12. 避免过度设计成 FineReport。
