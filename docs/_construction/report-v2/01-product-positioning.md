# Report V2 产品定位

## 背景

Report V1 已经完成了报表模块的关键后端闭环：

1. 发布版本。
2. 运行态隔离。
3. 后端受控导出。
4. 执行日志。
5. 前端接口接入。

这些能力证明了当前低代码底座可以支撑正式报表模块的核心安全边界。但实际使用后也暴露出明显产品问题：

1. 报表中心和报表管理职责重复。
2. 设计器默认进入空白 Sheet 画布，不适合普通后台报表用户。
3. 当前设计器入口和功能路径不清晰。
4. V1 更像技术验证，不适合作为低代码平台中的最终报表产品体验。

因此暂停 V1-E 渐进式优化，启动 Report V2 正式设计。

## 为什么停止 V1-E 渐进优化

V1-E 原目标是在 V1 前端基础上逐步改善体验，但 V1 的问题不是单点 UI 问题，而是信息架构和默认设计流程问题。

继续在 V1 页面上渐进优化会带来三个风险：

1. 继续保留“报表中心 + 报表管理”两个重复概念，用户心智仍然混乱。
2. 继续迁就 Sheet 画布作为默认入口，普通报表创建仍然门槛高。
3. 前端代码会在兼容旧体验和新增快速体验之间越来越复杂。

Report V2 应当重新设计产品信息架构、前端 UI 和设计器流程；V1 保留为技术验证和兼容实现。

## V2 定位

Report V2 是低代码平台底座中的正式报表模块。

它不是 FineReport 的完整替代品，而是面向普通后台项目的高频报表能力，目标覆盖 80% 常见需求：

1. 快速创建表格报表。
2. 支持参数查询。
3. 支持分页运行。
4. 支持后端受控导出。
5. 支持发布版本。
6. 支持运行态隔离。
7. 支持权限和数据权限。
8. 支持高级 Sheet 作为复杂布局能力，但不作为默认入口。
9. 支持未来扩展数据集、外部数据源、图表、打印、订阅，但第一阶段不做过大。

## V2 不是什么

Report V2 第一阶段不做：

1. 不做完整 FineReport 替代品。
2. 不做图表大屏。
3. 不做填报。
4. 不做打印分页。
5. 不做定时订阅。
6. 不做邮件发送。
7. 不做复杂 BI 建模。
8. 不做外部数据源泛化。
9. 不推翻 V1 已完成的发布、运行、导出、日志能力。

## 目标用户

Report V2 的默认目标用户是：

1. 业务后台开发者。
2. 项目实施人员。
3. 低代码平台配置人员。
4. 具备基础数据表理解能力的管理员。

它不是面向专业 BI 报表开发人员的复杂工具。

## 高频使用场景

第一阶段重点覆盖：

1. TMS 运单列表报表。
2. SRM 采购订单报表。
3. 在线学习平台学员学习记录报表。
4. CRM 客户跟进明细报表。
5. 审批、订单、工单、库存等后台明细报表。
6. 带查询条件、分页、导出的运营类表格报表。

## V1 必须保留

V1 的后端闭环是 V2 的底座，必须保留：

1. `report_definition`
2. `report_definition_version`
3. `report_execution_log`
4. `POST /admin/report/:id/design-preview`
5. `POST /admin/report/:id/publish`
6. `POST /admin/report/:id/run`
7. `POST /admin/report/:id/export`
8. `GET /admin/report/:id/versions`
9. 运行态只读发布版本。
10. 后端受控导出。
11. 执行日志 action 区分 `design_preview` / `runtime_run` / `runtime_export`。
12. 菜单、按钮、Casbin、数据权限体系。
13. SQL 数据集管理员限制和 SQL 安全守卫思路。

## V1 可以复用但不作为默认体验

以下能力可以复用，但不作为 V2 默认入口：

1. `ReportSheetCanvas`
2. `ReportSheetPreview`
3. `ReportInspectorPanel`
4. `ReportResourcePanel`
5. 当前 `sheet/cell/binding` 模型。
6. 当前 `query_config / layout_config`。
7. 当前 `sys_table / sys_table_field` 数据源发现能力。
8. 当前 table/sql dataset 配置能力。

## V1 建议废弃或重写

以下 V1 前端体验建议废弃或重写：

1. V1 报表中心页面体验。
2. V1 报表管理页面体验。
3. V1 设计器默认进入空白 Sheet 画布的流程。
4. V1 报表中心和报表管理重复的运行/导出体验。
5. 旧的“直接 Sheet 画布开始设计”的默认流程。
6. V1 中把报表中心和报表管理割裂成两个重复页面的交互方式。

注意：不要理解为 V1 完全废弃。V1 的后端闭环是 V2 的底座；V1 的前端体验需要被替换。
