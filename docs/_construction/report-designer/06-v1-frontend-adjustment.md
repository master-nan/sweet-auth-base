# 报表设计器第一阶段前端调整说明

## 调整原则

第一阶段前端只做必要调整，不重写设计器，不扩展复杂 UI。

原则：

1. 保留当前 sheet/cell/binding 设计器。
2. 保留当前 `ReportSheetPreview`。
3. 保留当前 table/sql dataset 配置能力。
4. 保留当前数据源发现交互。
5. 不新增外部数据源管理页面。
6. 不新增独立数据集管理页面。
7. 不做图表大屏。
8. 不做自由画布增强。

## 设计器页面

现有页面：

- `/frontend/src/pages/report/design/Index.vue`

保留内容：

- 顶部工具栏
- 左侧资源面板
- 数据集配置弹窗
- 参数配置弹窗
- join 配置弹窗
- sheet 画布
- 属性面板
- `ReportSheetPreview`

第一阶段调整：

1. 保存按钮继续保存草稿。
2. 预览按钮调用 `POST /admin/report/:id/design-preview`。
3. 发布按钮调用 `POST /admin/report/:id/publish`。
4. 预览结果展示继续复用 `ReportSheetPreview`。
5. 当报表状态为 `disabled` 时，设计时预览应禁用或提示不可预览。

不做：

- 不重做画布。
- 不增强自由布局。
- 不新增复杂组件库。
- 不做图表设计器。

## 报表管理页面

现有页面：

- `/frontend/src/pages/report/manage/Index.vue`

第一阶段调整：

1. 列表展示发布状态。
2. 列表展示当前发布版本号或发布时间。
3. 增加发布入口。
4. 增加版本列表入口。
5. 运行入口改为使用 `/run`。
6. 导出入口改为使用 `/export`。
7. disabled 报表禁用运行和导出。

不做：

- 不新增复杂审批流。
- 不新增外部数据源管理。
- 不新增数据集管理中心。

## 报表中心页面

现有页面：

- `/frontend/src/pages/report/center/Index.vue`

第一阶段调整：

1. 只展示可运行的 published 报表。
2. 运行时调用 `POST /admin/report/:id/run`。
3. 导出时调用 `POST /admin/report/:id/export`。
4. 参数输入保留现有方式。
5. 预览展示继续复用 `ReportSheetPreview`。
6. disabled 报表不应出现在可运行列表中。

关键规则：

- 报表中心不直接读取草稿效果。
- 报表中心展示的是发布版本。
- 修改草稿后，报表中心结果不应变化，直到再次发布。

## 版本列表

第一阶段可采用轻量入口，不做复杂版本对比。

建议能力：

- 查看版本号
- 查看发布时间
- 查看发布人
- 查看发布说明
- 标识当前运行版本

第一阶段不做：

- 版本 diff
- 版本回滚
- 版本复制
- 多环境发布

如需回滚，可在后续阶段补充。

## 导出交互

第一阶段从前端当前页 CSV 导出，调整为后端受控导出。

规则：

1. 报表必须是 published。
2. 前端调用 `/export`。
3. 后端控制最大导出行数。
4. 后端写执行日志。
5. 前端只负责下载文件和展示错误。

第一阶段可支持：

- `xlsx`
- `csv`

具体格式以实现成本为准，至少应支持一种后端导出格式。

## SQL 报表提示

SQL 报表风险较高。

前端建议：

1. 在 SQL dataset 配置区域显示安全提示。
2. SQL 字段推断失败时展示明确错误。
3. 发布失败时展示 SQL 安全校验错误。
4. 普通用户无权限运行 SQL 报表时展示权限提示。

不做：

- 不做复杂 SQL 编辑器能力。
- 不做 SQL 血缘分析。
- 不做 SQL 自动权限注入提示。

## 路由和菜单

第一阶段继续复用现有路由：

- `report_center`
- `report_manage`
- `report_design`

可以补充按钮权限：

- 发布
- 运行
- 导出
- 查看版本

不新增复杂菜单结构。

## 前端验收重点

前端完成后应能验证：

1. 设计器保存草稿。
2. 设计器设计时预览。
3. 设计器发布报表。
4. 管理页查看发布状态和版本。
5. 报表中心只运行 published 报表。
6. 草稿修改不影响报表中心运行结果。
7. 报表中心导出走后端接口。
8. disabled 报表不能运行和导出。
